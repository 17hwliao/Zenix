# 发行配置与用户首次配置建议

## 发行原则

音乐源由开发者自行收集用于本机使用和兼容调试，发行时不随软件提供脚本或已配置的源；用户自行导入、启用和排序。Zenix 提供接入能力，歌曲和个人资料由每个用户分别配置。

当前已配置 Windows x64 NSIS 安装包，执行 `npm run package:win` 输出到 `release/`，不自动上传发布。下表中的文件白名单由 `electron-builder.yml` 实现，用户数据继续保留在本机；配置默认值建议及统一导出建议仍单独注明实现状态。

## 发行包包含与排除清单

| 内容 | 发行建议 | 说明 |
| --- | --- | --- |
| 主程序、编译后的 UI、必要运行组件 | 包含 | 白名单包含 `dist/`、Electron 运行模块及图标；前端库已编译进 UI，不重复打包其 node_modules。 |
| Zenix 图标、开屏动画、合成音效 | 包含 | 属于软件体验所需资源，相关组件与来源见第三方说明。 |
| 导入与管理音乐源的功能 | 包含 | 用户自行选择文件、文件夹或地址；首次安装源列表为空。 |
| 开发者已安装的源脚本、源配置、访问密钥 | 排除 | 不复制 `sources/` 或开发者的用户数据目录。 |
| 测试源地址列表 | 不作为用户默认配置 | 当前代码仍有预设入口按钮；记录链接与捆绑脚本是两回事。若发行版连测试地址也不展示，需另行隐藏该预设区域，保留通用导入入口。 |
| 当前歌曲、下载文件、音频缓存 | 排除 | 不将个人听歌素材用作软件样本；首次安装曲库和播放队列为空。 |
| 喜欢、收藏、历史、自定义歌单 | 排除开发者记录 | 用户首次启动后建立自己的歌曲库存。升级时保留用户已有记录。 |
| 本地歌曲索引、封面和歌词缓存 | 排除 | 包含本机路径或个人使用记录；在用户电脑上重新建立。 |
| 背景照片、视频、头像、卡面素材、联系方式 | 排除开发者资料 | 以通用名片和默认视觉启动，背景选择允许跳过。 |
| 桌面歌词位置、锁定状态、浏览器存储、调试日志 | 排除开发者记录 | 用户设备自行生成，避免带入错误屏幕坐标和个人配置。 |
| Folia 参考目录、开发工具缓存、分析采样文件 | 排除 | 参考工程与开发资料不进入安装包。 |

“不打包用户数据”不等于删除这些数据。发行过程应只读取选定的应用文件，不通过清理开发者目录来制造首次启动状态。

安装器支持自选目录、桌面及开始菜单快捷方式；卸载不删除用户数据。GPL 原文、第三方说明与组件许可证位于安装目录的 `resources/`；Electron 的 `LICENSE.electron.txt` 与 Chromium 的 `LICENSES.chromium.html` 位于安装根目录。已发布的 Windows 0.1.0 安装包未签名。0.3.0 开发版接入自动更新及签名发布流程；Android 已有正式密钥，Windows / iOS 需要对应发行资料，详见 [自动更新与签名说明](automatic-updates.md)。

## 用户配置建议列表

以下是建议体验，其中注明“建议调整”的默认值尚未改动代码。

| 配置项 | 当前情况 | 建议 |
| --- | --- | --- |
| 音乐源 | 由用户安装，启用后参与请求 | 初次为空；先配置一个自己信任的源，播放成功后再添加备用源。 |
| 源顺序 | 按用户接入及设置顺序回退 | 主用源在前、备用源在后；保持现有顺序队列，全部失败后再提示。 |
| 在线音质 | 默认 `auto`，优先最高可用 | 默认保留自动；网络不稳定或希望减少等待时，用户选择标准/高音质。 |
| 本地歌曲 | 用户主动导入文件或文件夹 | 作为离线备用，不默认扫描整台电脑。 |
| 喜欢、收藏、歌单和历史 | 本机持久化，历史按歌曲身份去重 | 首次为空；按喜好建立自己的歌单。移除播放队列不删除库存。 |
| 音频缓存 | 默认开启，1024 MiB；支持 512/1024/2048/5120 MiB | 普通使用保留 1024 MiB；轻量设备选 512 MiB；自动缓存可淘汰，不作为永久备份。 |
| 自动缓存清理 | 按最近访问及容量清理，30 天未访问的项可淘汰 | 保留当前规则；清缓存不清喜欢、收藏、历史或导入的本地音乐文件。 |
| 播放音量 | 默认 75% | 建议首次改为 35%～50%，避免第一次播放过响；记住用户后续选择。 |
| 启动播放 | 队列可持久化 | 建议恢复曲目与队列但不自动发声；由用户点击播放。 |
| 个人名片 | 默认“我的音乐空间”，简介/联系等为空 | 不带入开发者昵称、邮箱和头像，用户填写时明确保存到本机。 |
| 主背景 | 首次允许选择图片或视频，也可跳过 | 先建议静态图片；视频作为可选项，避免默认提高资源占用。 |
| 环绕卡片封面 | 默认可随列表首曲，支持自定义图片 | 保留当前逻辑，用户可单独覆盖喜欢/收藏/历史等封面。 |
| 桌面 LRC | 横竖布局；字大小默认 28，玻璃不透明度默认 56% | 办公建议横向三行、系统字体、24～28 px、低饱和字色；选择合适位置后锁定。 |
| LRC 启动显示 | 保存用户开关和布局偏好 | 建议首次关闭，用户主动启用；升级时记住选择，重置异常窗口位置。 |
| 交互音效 | 当前默认开启，音量 85%，三类各五种 | 建议默认关闭或降至 15%～25%；进入/取消/滑动独立选择并允许试听。 |

推荐的首次使用流程：启动 → 可选背景 → 编辑名片（可跳过）→ 导入自己的音乐源或本地歌曲 → 搜索并试听 → 建立喜欢/歌单 → 按需开启桌面歌词。

## 当前配置存放位置

以下路径均相对于应用实际的 `app.getPath('userData')`，不是项目源码目录。Electron 在 Windows 上通常将应用用户数据放在 `%APPDATA%` 下；应以运行时返回的路径为准。[Electron 官方路径说明](https://www.electronjs.org/docs/latest/api/app#appgetpathname)

当前工程检测到旧版 `YzqxY Music Player` 数据目录存在时会继续使用它，因此更换品牌后仍可能沿用旧目录。不要仅按“Zenix”文件夹名判断所有数据所在位置。

| 路径或存储 | 实际内容 | 备份与迁移建议 |
| --- | --- | --- |
| `sources/index.json`、`sources/` 子目录 | 已安装源、脚本、配置与顺序 | 属于用户自己配置的内容；不进入发行包或公共示例。 |
| `library.json` | 本地文件路径、曲库索引、导入记录 | 音频原文件通常仍在导入位置；换电脑需重新关联路径。 |
| `personal-library.json` | 喜欢、收藏、近期历史、自定义歌单 | 优先备份；它是歌曲信息清单，不包含所有歌曲音频。 |
| `appearance/settings.json` 和 `appearance/` 媒体 | 背景选择及复制的图片/视频 | 用户私人内容，备份时可选择包含。 |
| `audio-cache/index.json`、`audio-cache/` | 可淘汰的音频缓存与索引 | 默认不加入配置备份，可重新获取。 |
| 旧版本的 `downloads/`（若存在） | 停用下载功能前的遗留文件 | 当前不读取或恢复下载任务，不自动删除用户文件；需要时可作为本地歌曲手动导入。 |
| `covers/`、`source-cache/covers/`、`source-cache/lyrics/` | 封面和歌词缓存 | 可重新生成，不随安装包分发。 |
| `desktop-lyrics-state.json`、`desktop-lyrics-bounds.json` | 桌面歌词锁定、横竖布局与位置 | 可备份偏好；换屏幕时不直接照搬坐标。 |
| 主窗口 Local Storage | 名片图片与资料、卡片层次、音效、音质、音量、队列等 | 当前没有统一导出入口；只复制几个 JSON 不能完整备份这些内容。 |
| 歌词窗口 Local Storage | 字体、颜色、字号、玻璃不透明度等 | 与主窗口配置分开，迁移需分别处理。 |

开发预览与正式应用的页面来源可能不同，浏览器存储也可能分开。不要将 Chromium 的整个存储目录作为公开配置模板；统一导出应在后续通过明确字段处理。

## 后续配置导出建议（未实现）

建议提供“导出个人配置”，由用户勾选：个人名片、背景与卡面图片、外观与音效、歌词偏好、喜欢/收藏/歌单、播放历史。

默认排除：源脚本与密钥、下载歌曲、音频缓存、临时播放链接、调试日志和本机绝对路径。喜欢与歌单保存歌曲标识及元数据；导入后重新解析播放地址。音乐源由用户在新设备上单独配置。

导出格式应包含版本号；媒体使用相对资源引用；导入允许预览并选择合并或替换。此建议不代表当前已经具备统一备份、导出或还原功能。
