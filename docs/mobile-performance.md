# 移动端资源策略（0.2.1）

保留玻璃、连续旋转和有限贴纸布局，Android/iOS 均使用原生音频播放器，音频不经过 React 状态或整个文件的内存数组。

- Android Media3：10–30 秒时间缓冲、4 MiB 压缩音频分配目标、取消回看缓冲；该数值不是整个应用内存上限。弱网缓冲仍由播放器处理。
- iOS AVPlayer：前向缓冲偏好 15 秒；系统可以根据播放条件调整。URLSession 按区段写磁盘，不把整曲保存在 Data 中。
- 贴纸仅为可视区域及 240 px 预读边缘挂载动画节点与封面，保留所有贴纸几何和歌曲条目，拖动时每 50 ms 更新可见范围。隐藏贴纸会卸载，浏览器何时回收解码缓存由 WebView 决定。
- 封面异步解码、延迟加载，播放时钟更新不会重复渲染未改变的 Art 组件。iOS 系统媒体封面缩略至 256 px，本地导入封面缩略至 512 px。
- 后台隐藏页面时暂停背景视频、CSS 动画及 React 播放快照更新；返回前台取一次完整快照。后台音频由原生服务继续处理。
- 原生播放进度使用小快照；读取缓存、音乐源或浮层配置时只复制对应字段，不复制整个歌单和歌曲库。
- 音乐源运行器只保留目录与一个当前源，匹配记录最多 32 项；历史最多 300 首，歌词缓存最多 100 份。歌曲缓存占磁盘预算，不等同于常驻内存。

这些是代码层面的优化。当前没有连接 Android/iPhone 真机，尚未取得相同歌曲、源、背景与设备条件下的 PSS / Instruments 实测对比，不能宣称达到某个 MB 数值或绝对最低占用。Debug 包也不等同于正式性能基准。

后续设备验收可分别记录空闲首页、搜索、播放五分钟、后台音频和悬浮歌词状态：Android 使用 adb shell dumpsys meminfo com.zenix.musicplayer；iOS 使用 Xcode Instruments Allocations / VM Tracker，区分 App、WebContent 和系统媒体进程。视频背景与高分辨率封面会额外占用解码内存。

## 2026-10-03 回归补充

固定视口测试中，500 首歌只挂载 23 个动画贴纸节点。Android 新增后台 30 秒释放源脚本 WebView、调用时重建的策略，仍需真机检查后台切歌与恢复。APK 编译及 lint 通过（0 错误、28 警告），iOS 页面构建与同步通过；设备 RAM 降幅尚未测得。测试边界、桌面对照与复现方式见 [本轮报告](regression-memory-2026-10-03.md)。
