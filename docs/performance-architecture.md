# Zenix 性能与架构调整

日期：2026-09-30。当前成果用于本地验收，尚未上传或执行发行打包。

## 播放路径

`播放器 → 一次本地缓存查询 → 按安装顺序逐源解析 → 媒体协议代理 → 音频解码`

- 源队列保持用户设置的接入顺序；不会同时解析所有源，也不会按测速重新排序。
- 音质仍按用户偏好回退。自动模式优先高解析、无损、高品质、标准；仅在有可靠歌曲格式信息时跳过确定不存在的格式。
- 合并多次缓存 IPC 和重复文件检查。已下载的歌曲优先离线播放，再检查对应音质的音频缓存。
- 删除解析成功后的额外音频探测请求，由实际播放器完成音频验证；失败仍通过原有重试流程继续。
- 网络连接异常、超时或服务端失败时，避免继续对同一故障源重复尝试全部音质。解析保留期限，媒体连接等待响应头上限为 8 秒；此期限不截断已经开始传输的长音频。
- 播放与缓存共用同一网络流，第一块音频立即交给播放器。每块缓存写入完成后才继续拉取，内存不会累积整首音频。
- Chromium 若取消只为读取元信息的请求，后台补缓存延后 6 秒，并限制后台任务数量。不能完整缓存的响应继续正常播放。
- 相同目录搜索和封面请求合并；目录缓存 60 秒。保留源独立脚本接口、音频 Range、鉴权地址刷新与本地备用入口。

真实首播时间仍包含外部服务响应与音频解码时间；本次没有进行用户歌曲的耗时对照测试，因此不提供未经测量的速度百分比。

## Electron 责任边界

| 模块 | 职责 |
| --- | --- |
| `electron/main.cjs` | 应用生命周期、窗口、IPC 接线 |
| `electron/sources.cjs` | 安装记录、源能力与目录、解析会话协调 |
| `electron/runtime/source-runner.cjs` | 脚本沙箱生命周期、调用期限、并发引用和网络取消 |
| `electron/runtime/source-metadata.cjs` | 兼容脚本元信息与完整原文信息 |
| `electron/runtime/source-network.cjs` | 域名检查、重定向、大小受限读取、并发 DNS 查询合并 |
| `electron/runtime/media-protocol.cjs` | 受限文件路径与媒体 Range 协议 |
| `electron/runtime/audio-capture.cjs` | 单流播放与磁盘缓存写入 |
| `electron/runtime/bounded-cache.cjs` | 有数量、字节与有效期上限的缓存 |
| `src/core/sourcePlayback.ts` | 顺序源回退、音质选择、状态提醒 |

本次通过 Zenix 自有模块拆分和职责收拢实现，未引入参考项目的整套 Electron 架构。沙箱、上下文隔离、脚本网络限制保持启用。音乐源协议兼容与项目/依赖许可证见根目录 `THIRD_PARTY_NOTICES.md`。

## 内存控制

- 脚本按需启动，只保留一个空闲的温热运行器；并发中的请求不会被回收。空闲 20 秒释放，后续需要时重新初始化。这会用少量再次初始化时间换取更低常驻占用。
- 封面内存缓存最多 32 项且合计不超过 8 MiB；目录缓存最多 12 项；播放会话最多 48 项；导入预览、封面提示同样有上限。DNS 只合并最多 64 个在途查询，不跨请求复用旧域名地址。
- 贴纸墙仅挂载视野与预加载边界内的卡片，聚焦卡保持挂载；完整队列数量和布局数据不变。
- 自定义背景展示时不运行底层两张 WebGL 背景；默认背景模块按需加载，单层渲染像素上限降低到 409600。
- 主窗口隐藏时移除封面图像、背景视频和着色器，停止视频亮度采样；音频与桌面歌词同步继续工作。
- 关闭桌面歌词销毁它的窗口进程，重新打开恢复数据和位置；歌词完整数组仅在改变时发送，播放时间使用小型增量消息。收藏摘要直接查询，避免每次同步克隆整个私人曲库。
- 歌词文字不变时跳过重新排版。音效最多三组、每组两个播放器，切换方案和关闭时释放旧资源。
- 原音频磁盘缓存策略保持容量限制和 30 天/LRU 清理；磁盘存储和 RAM 分开统计。
