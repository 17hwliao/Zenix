# 回归测试与内存优化（2026-10-03）

## 结论

32 项自动测试、12 项桌面实际进程回归通过，Android APK 构建、签名校验及静态检查通过，iOS 共享页面构建与同步通过。没有连接手机、Android 模拟器或本地 iOS 模拟器，**不能将结果表述为全设备验收完成**。

移动端 500 首歌的固定视口测试中，挂载动画贴纸从全部 500 个改为 23 个，减少 95.4%；完整歌曲列表和几何布局保留。这是节点数量对比，不是手机 RAM 降幅。

桌面同一生成数据集的内存读数有升有降，尚未证实整体、稳定的常驻内存降幅。保留有测试依据的资源修复，不承诺绝对最低内存。歌曲磁盘缓存、歌单和完整桌面听歌历史继续保留。

## 改动

- 缓存取消：等待尚未完成的文件打开/写入，再关闭句柄、删除临时文件、释放读取锁。延迟文件打开的测试检查打开与关闭数量一致、无残留临时文件，修复了取消竞争导致的句柄泄漏。
- 音频格式探测：备用缓存路径只复制前 64 字节，避免小切片引用整个网络块。
- 移动贴纸：视口外卸载整个动画节点和封面，焦点贴纸始终存在。Android/iOS 共用此界面。
- Android 音乐源：后台 30 秒释放源脚本 WebView，下次调用重建；关闭与脚本调用使用同一同步机制。原生后台播放器保持工作，仍需真机回归。
- 桌面主页：隐藏时暂停卡片 RAF，返回时恢复，不停止音频。
- 桌面贴纸：静止时预读边缘由 1.5 格降至 1 格，拖动时仍为 1.5 格。此基准视口挂载数量仍为 35 个，不据此声称该场景内存下降。
- 随机播放：内部上一首导航栈最多 300 项；不裁剪桌面持久化听歌历史，另有 301 条保存、重载测试。
- 本地音频协议显式设置字节队列上限，检查 Range、HEAD、取消及错误响应。对照证明本机默认策略已经有限流，此项不计作内存降幅来源。
- Android 补齐 Media3 不稳定 API 显式 OptIn、修正 Windows SDK 路径转义，没有新增 lint baseline 或禁用检查规则。

封面缩略、着色器快照、Chromium GPU 缓存参数等实验没有稳定收益或出现退化，已撤回，保留当前玻璃与动画外观。

## 测试范围

### 自动测试：32 / 32

`npm test` 使用 Node 测试运行器，不增加测试框架依赖。

- 有限布局：0、1、2、5、12、25、108、120、300、500 首，无重叠、有效尺寸与焦点位置。
- 移动节点挂载：0、1、25、120、500 首，固定视口下节点有界。SSR 使用原生接口替身，不代表真机播放。
- 中英文 LRC、偏移/翻译/多时间标签、VTT、QRC、YRC/KRC、空歌词和无时间歌词；TTML 未覆盖。
- 歌单、喜欢、收藏、历史去重/持久化，队列、进度、音量和随机回退。
- 切歌取消旧解析、按安装顺序及音质回退、超时与取消监听清理。

### 桌面实际进程：12 / 12

实际 Electron 主进程、IPC、生产页面及媒体元素，采用独立测试数据目录。自制 120 首不同记录的 90 秒静音 WAV、1024 px 封面及中英文歌词。音乐源也是生成的 fixture，搜索、解析不访问外网，不读取或修改现有用户配置、源脚本和歌曲。

检查：数据完整/可视节点有界、媒体时钟推进、进度跳转、歌单管理、历史去重、源安装/搜索、闲置运行器释放、歌曲放大/Escape、桌面歌词置顶标记、竖版/预览三秒回位/锁定/关闭销毁、主页滚动/管理跳转、首页搜索进入对应单首贴纸且无下载按钮。

完成首页与音乐空间八次往返、最小化/恢复采样，无捕获到的 renderer 错误或崩溃。已检查应用自身 `capturePage` 渲染截图。原生窗口检查时 Windows 已锁屏，未声称完成解锁桌面的真实鼠标边缘遍历或跨应用置顶验收。

第三方源在线成功率、弱网、真实音频格式、视频背景和长期后台播放不在本轮隔离测试的覆盖范围。

## 内存对照

MiB；各阶段等待后一次采样，非全程峰值。相同生成数据、视口和动作顺序，无强制 GC 或工作集裁剪。短时测试不能代替多小时压力测试。

| 场景 | 修改前私有驻留 | 修改后私有驻留 | 修改前工作集总和 | 修改后工作集总和 |
| --- | ---: | ---: | ---: | ---: |
| 首页 | 180.8 | 175.9 | 456.6 | 452.3 |
| 音乐空间 120 首 | 323.0 | 302.7 | 727.5 | 709.2 |
| 播放 | 227.1 | 278.3 | 632.3 | 685.7 |
| 桌面歌词打开 | 246.2 | 234.8 | 740.9 | 731.7 |
| 桌面歌词关闭 | 208.4 | 212.4 | 617.6 | 624.0 |
| 源运行器工作后 | 230.2 | 233.5 | 727.4 | 732.9 |
| 源运行器闲置回收后 | 202.3 | 200.1 | 589.0 | 586.9 |
| 八次页面往返后 | 249.5 | 283.6 | 637.2 | 755.1 |
| 最小化播放 | 231.1 | 257.6 | 618.8 | 729.2 |
| 恢复窗口 | 214.7 | 243.0 | 602.5 | 714.6 |

修改后本组私有驻留约 176–303 MiB。首页、首次音乐空间、歌词打开下降，播放与反复切换读数更高，不能选低点计算全局优化百分比。多轮实验存在 GPU/Chromium 缓存和回收时机波动；未确认新的 renderer 累积，但仍需长期重复实验判断趋势。

私有驻留为实际驻留 RAM；工作集包含共享页，跨进程相加可能重复计数；私有提交不是物理 RAM，GPU 专用显存另计。用户先前的 472 MB 与本组场景、运行时长和统计口径不同，不能直接计算降幅。

64 MiB 生成文件的 Node 独立进程对照：默认策略与显式字节队列在未消费时均只读取 131,072 字节；RSS 增量约 8.35 / 8.42 MiB，没有证据表明默认路径会读取整曲，不将其列为优化收益。

本机原始记录位于忽略目录 `release/profiles/`，对应 `baseline-v2/measurement.json`、`final-optimized/measurement.json` 和 `stream-backpressure/measurement.json`。早期基准断言曾误要求全部 120 首挂载，现已改为数据完整且可视节点有界，该断言差异不作为程序 bug。
