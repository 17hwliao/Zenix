# 移动动画性能审查与本地候选验收

日期：2026-10-10。范围由用户明确授权：歌曲详情页进入 / 退出、页面切换、音乐空间进入和贴纸聚焦，以及这些界面的原生数据更新。基线为已发布的 v1.0.0 / r28（源码 5bd93fb）。本轮不是全仓库重复审计，不包含正式发布。发现 r30 聚焦仍有长帧后继续修复，最终本地联合测试候选为 r32。

## 确认问题与修复

| 优先级 | 位置 | 触发与影响 | 当前处理 |
| --- | --- | --- | --- |
| P1 | `src/mobile/StickerSpace.tsx` | 贴纸聚焦同时逐帧修改 left / top / width / height，镜头也运动；每次焦点计算重复执行完整布局。手机原版测得聚焦单帧间隔最高约 266ms。r30 的 Framer 投影仍反复测量布局，镜头每 50ms 刷新整个空间。 | 保留 PC 的拼贴目标几何、焦点展开和周围让位，缓存布局并直接取得镜头目标；后续改用原生 Web Animations transform 投影，镜头移动前挂载整个扫过视口、结束后才重新裁剪。 |

| P2 | `android/app/src/main/java/com/zenix/musicplayer/PlaybackService.java` | 相同封面重复返回时仍替换当前媒体元数据并发送完整快照，放大界面刷新开销。 | 相同 URL 不再重复修改媒体项或发出状态。 |

歌曲管理列表仍是独立入口。贴纸点击只改变空间焦点，不切歌、不自动打开全屏；搜索追加不改变既有焦点 / 浏览位置。几何插值、收回、相邻让位、镜头移动和快速开关均有 Chromium 交互回归证据。

## 真机基线与测量限制

PKR110 / Android 16，原安装 r28，未启用 WebView 调试的三轮测试：

| 操作 | 三轮 p95 帧间隔的中位数 | 最长单帧间隔 |
| --- | ---: | ---: |
| 首页到设置 / 设置到源 | 16.7ms | 33.4ms |
| 首页到音乐空间 | 116.5ms | 449.3ms |
| 贴纸聚焦 | 166.4ms | 266.3ms |
| 详情页打开 | 299.7ms | 499.4ms |
| 详情页收起 | 299.6ms | 349.6ms |

这是 WebView requestAnimationFrame 的帧间隔，不能等同于 SurfaceFlinger 实际呈现帧率。测试使用程序点击，尚不能替代用户实际触摸和不同温度 / 电量 / 封面冷缓存下的体验。启用调试后的同版复测明显更快，存在运行状态差异；不使用调试前后的不同条件宣称优化幅度。当前设备显示模式为 60Hz，不据此承诺 90 / 120fps。聚焦 ready 标志只表示选中样式已建立，不表示整个动画结束。

证据保存在本地 `release/diagnostics/mobile-performance-r28-device.txt` / `.json`；调试采样另存为 `mobile-performance-r28-traced.txt`、`mobile-cpu-r28.json`、`mobile-trace-r28-summary.json`。这些诊断不上传用户资料。

## 验收结果与联合测试候选

- 35 项针对性回归通过，TypeScript 与 Android Web / 原生 Release 构建通过。日志：`release/diagnostics/mobile-performance-optimization-tests.txt`、`mobile-performance-r30-web-build.txt`、`mobile-performance-r30-native-build.txt`。
- 最终联合测试候选为 `release/performance-r32/Zenix-Android-1.0.0-r32-performance-candidate.apk`。SHA256：`6ba4e6b3997eacae63c01f90132acfa2b5d2635c4b87a0917295699e34bb4961`，大小 6,958,959 字节。公开版本 1.0.0，内部构建 32。后续用户授权安装包清理，未发布的过程候选 r30 / r31 已删除，测量记录保留。
- 原正式 r28 与候选实际证书均为 `b40080130e2186eba857ea2778350b88fe896c33cc9e0116493022e5adb8514a`，包名不变；r28→r30→r31→r32 均通过 ADB 覆盖安装，没有卸载主应用或清空资料。拉取实际手机 r32 APK，SHA256 与候选一致。
- 手机恢复授权后，r30 三轮未调试后测完成，资料摘要、配置摘要、保留标记与 r28 一致。详情收起 p95 中位数 16.7ms、最长 16.8ms；详情打开 p95 中位数 16.8ms，但仍有 149.9ms 的打开长帧；进入空间 p95 中位数 16.7ms、最长 149.9ms。贴纸聚焦 p95 中位数仍 199.7ms、最长 283.2ms，**不达标，继续修复**。证据为 `mobile-performance-r30-device.txt` / `.json`，此前连接失败输出已被此次成功后测替换。
- 后续 8 项移动针对性回归通过，覆盖新版原生 transform 动画、几何展开 / 重排 / 恢复、设置页最新歌单、快照稳定引用，以及详情页快速开关。日志为 `mobile-performance-compositor-tests.txt`；前一轮桌面补测曾出现 433.8ms 的进入延迟，后续变更后重测进入 271.7ms / 退出 213.5ms，桌面数字不替代手机验收。
- r31 贴纸聚焦 p95 中位数 16.7ms、最长 16.8ms，三轮无超过 50ms 的帧间隔；详情首次打开仍有 116.6ms 间隔。原生 gfxinfo 采样作为补充记录保留，包含启动和测试过程，不能将其汇总指标当作某一动画的帧率。
- r32 全部八类操作的三轮 p95 中位数约 16.7ms。贴纸聚焦最长 49.9ms、详情收起最长 16.8ms，两者无超过 50ms 的帧间隔；详情打开最长 83.3ms、进入空间最长 66.6ms、空间回首页最长 66.6ms，三轮各一次超过 50ms。证据 `mobile-performance-r32-device.txt` / `.json`。不宣称零掉帧或稳定 120fps。
- r32 首次进入空间 / 详情仍有偶发绘制停顿，属于后续联合测试观察项；后两轮详情打开最长约 16.8ms。低电量、长时间播放、密集拖动、不同 WebView / 手机和封面冷缓存没有完成覆盖，不能把当前手机结果泛化到全部设备。
- r30 / r31 / r32 的个人资料摘要、源 / 背景 / 名片配置摘要和保留标记均与 r28 基线一致。原加密文件本身因正常状态写入发生变化，不以加密字节相等替代逻辑资料比较。原数据喜欢 / 收藏 / 自建歌单均为空，历史两首；非空集合的保存 / 移除由隔离回归覆盖，不伪称此轮真机含非空集合验收。
- 最后一次背景优化后 Chromium 交互回归通过（`mobile-performance-background-tests.txt`），Android Web / 原签名 Release 构建通过（`mobile-performance-r32-web-build.txt`、`mobile-performance-r32-native-build.txt`）。截屏检查确认手机贴纸拼贴空间仍存在。
- 用户在 r32 普通启动后实际体验并回复“明显顺畅，继续联合测试”。辅助包 `com.zenix.musicplayer.test` 已卸载，未留 ADB 转发或 WebView 调试 socket，主应用保留普通启动。
- 未提交、推送或上传候选；正式签名更新清单仍指向 r28。更新实现、发行密钥和既有下载工件未修改。没有验证新的正式更新链路，不宣称本候选已通过正式发布验收。

当前交付：已安装的 r32 原签名本地联合测试版、源码修复和本审查记录；未正式发布。下一步收集测试人员在首次打开、不同设备和长时间使用下的反馈，再与后续问题合并处理。任何新字节候选须使用 r33 或更高构建；正式发布仍须按 AGENTS.md 完整验收应用内更新链路。
