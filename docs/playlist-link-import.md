# 音乐平台歌单链接迁移（本地实现）

PC 与 Android 共用“歌单分享与迁移 → 从音乐平台带来歌单”入口。粘贴分享文字或链接，解析后核对歌单名称、平台、原始总数、可导入数量和前 30 首曲目，点击“导入为新歌单”保存。可以修改新歌单名称；同名自动加后缀，不覆盖原歌单，也不更改正在播放的队列。

首批适配 QQ 音乐、网易云音乐、酷我音乐的公开歌单。QQ 支持网页歌单、移动分享页及 c6 官方短链接；网易云支持带 hash 的旧网页链接及官方短链；酷我支持 playlist / playlist_detail 链接。仅输入歌曲、专辑或个人主页链接不能当作歌单导入。

## 读取方式与完整性

- QQ：读取公开歌单元数据，必要时使用 `uniform_get_Dissinfo` 分页（每页 100 首）。旧接口失效或返回不足时使用分页路径。保留歌曲 MID、数字 ID 与 media MID，不逐首按标题搜索代替原始歌曲。
- 网易云：先取得歌单曲目 ID 顺序，再按需分批补全歌曲详情。补全接口的返回顺序不会改变原歌单顺序。
- 酷我：分页读取公开歌单元数据，区分平台声明的总数与实际返回的条目。

一次最多读取 5000 条，并受既有歌单交换的 2 MiB 上限限制。超过上限时明确标记部分结果。分页失败、重复分页、总数缺失、下架或缺少必要信息的歌曲都不会被标成“完整迁移”。不完整结果必须额外勾选知情确认才能导入；同一平台的重复歌曲按 ID 合并，并显示合并数量。取消解析不会保存歌单。

歌单只保存元数据；平台账号、Cookie、会员权限、音频或带认证的播放地址不迁移。私密歌单或登录后可见的内容需要用户先在原平台设置为公开；不提供登录抓取或私有接口绕过。

## 两端播放与网络边界

使用 `lx.playlist:catalog` 作为目录身份，仅表示公共平台元数据，不是新增播放源；其中的冒号也使它不会与可安装源的合法 ID 碰撞。播放仍遍历已安装且支持该平台的音乐源，原始 ID 直接进入既有 LX 解析链，不额外安装源或静默改源配置。封面与歌词仍由既有公共目录读取及缓存。缺少可用音源时可以先保存歌单，导入成功不代表音频必定可播放。

读取通道只允许列出的平台官方 HTTPS 域名、默认 TLS 端口，每次重定向重新检查。原有公网 DNS 检查、实际连接地址固定、Android 的受限 VPN Fake-IP 兼容策略与 TLS 校验继续生效。没有请求平台登录态，也不发送用户自定义认证头；请求 25 秒上限、响应 4 MiB 上限，整次解析两分钟预算。该通道不调用更新模块、不改变音乐源网络权限。

## 本地核验事实

自动用例覆盖链接识别、分页、原始 ID / Unicode 保留、顺序、去重、私密失败、取消、部分结果确认、重定向逐跳校验和 Android 使用已安装兼容源解析。新功能保持本地，不因开发或编译自动提交、打包或发布；未执行手机测试。

收尾检查：新增 8 项回归通过；连同移动 SSR 和上一轮功能的定向检查 21/21 通过。Android 生产解析器 JVM 用例通过；实际 React / Chromium 移动界面回归通过，包括 320 / 390 / 430 宽度、部分清单确认、解析不写入及确认后保存。首次并行跑的界面用例在原有长按菜单步骤超时，隔离重跑两次通过，没有删除断言或将原失败日志改写为成功。两端前端构建、Android Java 编译通过；保留既有大分块与弃用 API 警告。
