# 封面故障与模块隔离审查

基线：main `3d4f10e`，公开版本 1.0.4 / build 51。此次修复仅在本地，没有发布、安装或修改用户配置与歌单。审查按功能入口和关键调用链覆盖共享前端、Electron、Android、存储、网络和更新发行边界；不是逐行验证全部源码、第三方依赖或所有厂商设备。

## 故障定位与此前遗漏

从当前保存的《Waiting for Love》元数据复现了酷狗封面失败：旧 `https://media.store.kugou.com/v1/get_res_privilege` 请求被 TLS 主机名验证拒绝，证书的 `*.kugou.com` 不覆盖该二级子域。它在历史提交 `3b40ea3` 中引入，不是此次 r51 新增加的接口。之前的搜索适配回归检查了返回歌曲和错误状态，没有覆盖真实封面元数据请求、图片下载和浏览器解码，因此遗漏了这条失效链路。

现场核对中 QQ 图片可以下载，不能将所有封面失败归为 QQ 接口失效。酷狗搜索返回的 Image 字段转为 HTTPS 后也能正常下载。已有歌曲缺少该字段时，`https://m.kugou.com/app/i/getSongInfo.php` 返回 album_img；音频付费状态不妨碍读取已有的专辑元数据，代码不使用响应内的音频地址。

## 已确认并修复

| 优先级 | 问题与触发条件 | 修复 |
| --- | --- | --- |
| P1 | 酷狗封面依赖证书不匹配的旧接口。搜索与播放可以成功，封面仍全部失败。 | 搜索直接携带图片提示；旧歌曲通过有效 HTTPS 元数据接口恢复。优先专辑图，缺少时使用歌手图。保持 TLS 与公共地址验证，不申请新 HTTP 权限。 |
| P2 | 封面失败响应也标记缓存一天；CoverArt 一次失败后一直停留在占位图。 | 失败响应 no-store；自有封面 URL 加独立资源修订参数，绕过旧的负缓存；界面最多补试两次，网络恢复事件可重新尝试，防止无限请求。 |
| P2 | 多张封面一起请求，下载时限包含连接池排队，后排请求尚未执行就可能失败。 | SourceArtwork 独立调度，两项并发、最多 128 个在途条目，同图去重；图片下载预算从获得执行槽位后开始。该预算与音乐按状态解析等待无关。 |
| P2 | 自定义封面和歌词调用能设置或清除音源整体错误状态，污染播放诊断。 | 两类元数据调用不再读写播放/搜索健康状态；各自取消只销毁自己的运行任务。 |
| P2 | 清缓存与迟到的封面/歌词写入竞争，旧任务可能重新写回缓存或删除新任务文件。 | 缓存写入、清理串行化，按 epoch 丢弃旧写入，不再用迟到任务删除新文件。磁盘写入失败不阻断有效图片显示或音频播放。 |
| P2 | 系统 MediaMetadata 对封面地址抛错时，会从选歌流程直接抛出。 | 系统媒体信息失败降级为文字，整个接口不可用时也不阻断选歌/播放。 |
| P2 | 搜索、首页集合、本地歌单与播放条的封面地址恢复规则不同。 | 统一 trackCoverUrl / CoverArt；保留原歌曲 ID、收藏、历史与歌单结构，不为恢复图片迁移或重建用户资料。 |

## 隔离边界

- **封面服务**只负责图片提示、下载队列、内存和图片磁盘缓存。它不操作播放选择令牌、自动平替、个人资料或更新清单。
- **播放与歌词**保留各自请求和状态；保留原三次平替、状态等待、取消、漫游和音频缓存逻辑。封面/歌词成功不能清除真实播放错误，失败不能将音源标为播放失败。
- **元数据存储**共享明确的清理协调器，以免两个功能同时写删同一缓存目录；独立不等于没有必要的存储协调。歌单、配置和音频缓存的格式与身份不变。
- **更新**仍使用独立的可信网络、签名与工件核验；没有修改其生产实现、发行配置、公钥、APK 签名身份、版本号或正式清单。
- **移动端**沿用独立原生封面/播放通道；共享目录适配生成器同步校验。没有改贴纸布局、聚焦动效或移动播放策略。暂停维护的 iOS 未在此环境编译或实测。

审查同时复核播放取消与自动平替、搜索分页/同词重试、歌词迟到响应、源权限、缓存、资料恢复、统计、歌单交换、局域网与升级入口的边界。未由这次证据确认的疑点没有扩大重构。一次审查不能证明所有功能永久无冲突；此处的结论限于上述边界及实际验证。
