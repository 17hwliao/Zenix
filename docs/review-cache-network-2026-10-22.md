# v1.0.4 缓存与网络占用维护审查

范围：PC 与 Android 的播放选择、单曲循环、缓存提交/命中/清理、错误恢复、音乐源脚本生命周期、歌词/封面、取消、个人资料与更新/发行入口；包含前轮已获用户实机认可的贴纸单指修复及本次全部未提交改动。沿用已有播放器、贴纸布局、三次平替与状态等待，不改发行身份、公钥、资料目录或更新网络策略。第三方服务可用性、所有音频格式和所有设备不属于本次已证明范围。

## 已定位并修正

- 桌面 `SourceManager.stream` 在缓存完成后仍把相同 token 的 Range/循环请求发往音源。现在每次请求先找磁盘缓存，命中直接用本地范围响应；无需刷新过期 URL，音源关闭后仍能读取已有完整缓存。
- Chromium 收到最后一块声明长度的音频后可能取消 reader。原捕获器只在下次读到 EOF 时提交，可能触发整首补下载。现在等在途写入收拢，长度及音频头满足条件时正常提交；不完整、取消缓存写入及 HLS 仍不算整首离线。
- 音乐源调用完成后，PC 的暖运行器及 Android 的脚本仍可接受后台 HTTP。现在取消调用残留请求，拒绝空闲 HTTP；Android 队列项绑定原调用序号，旧请求不会借用下一调用的权限。慢解析本身不按总时长中断，不关闭共享更新连接池。
- Android 已完整缓存的当前曲在第一轮结束后切到 cache-only 数据源，后续循环及重新选择完整缓存不提供 HTTP 上游。磁盘缺块是显式错误，走原恢复路径，不静默重新下载；关闭自动缓存时当前已有完整缓存仍可继续读。
- 自定义歌词源原先优先重新请求歌词，仅 LX 源优先读文件。现在各类源统一优先读已有歌词缓存。

## Review 发现及修复

1. **P1，错误恢复重新命中坏缓存。** 新增 stream 本地命中若不处理强制解析，会把播放器已拒绝的字节再次送回。桌面强制重新解析会丢弃对应缓存及别名；丢弃期间禁止同 key 新建缓存写入，避免旧文件清理误删新提交。Android 显式完整缓存读取失败先串行丢弃该资源，再进行原恢复，不删除个人记录。
2. **P2，后台补下载的格式校验不一致。** 后台路径曾仅排除常见文本，可能把任意二进制当完整音频。统一使用有限音频头校验，并收集跨短分块的前缀，避免把合法分块误拒绝。音频头通过仍不等于解码必定成功，保留解码失败恢复。
3. **P2，缓存开关边界。** 当前曲从完整缓存播放时关闭自动缓存，不能拿缓存的空网络权限重新连网。保留当前 cache-only 读取及相同 key；开关继续控制后续自动写入。
4. **P2，发行验证范围遗漏及文案。** 实际 Windows 工件复核补入 audio-cache、audio-capture、source-runner 三个本次变更文件；发行元数据不再把固定的“没有真机安装”文案套用于每轮，验证范围以本轮发行说明为准。

## 验证与边界

本地全套回归 187 通过，0 失败，0 跳过。定向覆盖实际磁盘缓存和 HTTP 请求计数：首次一次音频请求，三轮同 token 重播、Range、HEAD、缓存重载无新增 HTTP；明确拒绝缓存后强制解析取得新字节，下一轮再次本地命中。覆盖最后一块取消提交、缓存别名、短分块音频头以及独立运行器取消。Android 生产编排在 JVM 执行，保留三候选、取消和状态等待检查。

Android 原生辅助场景使用隔离缓存和真实 Media3 解码器验证三次播放、无 HTTP 上游及缺块拒绝，并检查实际 ScriptEngine 在调用完成后拒绝空闲 HTTP、下一调用可复用。具体设备结果与实际工件身份随发行说明记录，不以编译或 instrumentation 外层退出码替代业务断言。

“播放结束”不自动等于完整缓存：空间不足、清理/驱逐、损坏、未完整收到字节、超过单曲缓存上限及 HLS 分段均可能继续需要网络。完整命中保证的是该音频不重复请求；更新检查、新搜索、未缓存封面/歌词、用户启用的遥控/局域网功能属于独立任务，不能宣称全应用永久零流量。

可选后续：在诊断页区分音频、脚本、元数据与更新的请求计数，帮助用户定位总网络占用；这是可选方向，本轮不增加常驻网络监控或新的遥测上传。
