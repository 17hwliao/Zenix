# 安全边界与稳定性修复流程

范围：Windows 与 Android 当前维护代码；保留视觉、源接入顺序、音质降级、个人数据与歌曲库存。

## 处理顺序

1. 输入边界：脚本、歌词、网络响应先限制输入和解压输出；拒绝超额并发。
2. 网络边界：域名规则检查 → DNS 解析与地址检查 → 绑定同一结果建立连接；每次重定向重新执行；跨来源清除敏感请求头。
3. 任务边界：每次播放选择拥有独立取消令牌；切歌/暂停取消旧解析与请求，迟到结果不能切换播放器；备用源继承当前位置。
4. 状态边界：配置按顺序原子写入；Android 主线程只修改小型播放状态，磁盘事务在后台合并执行，失败显示且可重试。
5. 存储边界：终身去重采用持久化索引，内存保持有界；缓存限额覆盖音频与源元数据，清理不删除用户歌单与音乐源。
6. 发布边界：安装包使用内部构建号命名，检查版本/签名/摘要后先上传安装包，再替换签名更新清单；失败不得宣称发布完成。

## 本次实现与检查记录（2026-10-07）

R1–R12 已落实代码修改，下面的运行验收尚未执行，不能视为通过：

- 输入：Windows 的源解压最多 4 MiB 输出、2 个并发，侧载歌词最多 2 MiB 输入，KRC 使用异步有界解压。目录 JSON/歌词/封面读取均有响应上限。
- 网络：Windows 使用 Undici 的自定义 DNS lookup 绑定校验地址；Android 使用 OkHttp 安全 DNS，脚本与 Media3 共用逐跳重定向规则，HLS 子请求也经过该数据源。禁止私有地址、HTTPS 降级及跨来源敏感头透传；域名查询和脚本请求队列有上限。
- 应用入口：主窗口禁止网页导航，应用 IPC 只接受主窗口/歌词窗口的主 frame；独立锁窗口仅可发送解锁事件。音乐源 IPC 继续保留独立隔离入口。
- 播放：原生和桌面取消均能终止对应网络/脚本任务；迟到结果由代次检查丢弃。Android 换源先 seek 再 prepare，准备失败仍保留原位置；随机队列不循环时用尽后停止。
- 配置：桌面串行原子替换配置；Android 播放模式、队列、缓存设置一次提交内存，后台合并 AtomicFile 写入，磁盘锁不占用读取锁，失败重试并向界面显示。
- 漫游：桌面采用 IndexedDB，Android 采用 SQLite。旧记录先完整迁移并提交再去掉旧 JSON/localStorage 中的 seen；迁移或保存失败停止推荐并保留原记录。内存只保留 512 个近期标识，终身去重索引不淘汰。
- 缓存：Windows 封面/歌词和 Android 歌词独立限额为音频预算的 1/8，最低 8 MiB、最高 64 MiB，30 天过期。缓存页面展示元数据用量，清除同时清元数据；清理代次阻止旧请求重新填回。Android 的音频/歌词清理在后台执行。
- 搜索：移动端可选“本地音乐”，无在线源也可检索已导入歌曲，并合并去重全部音乐搜索结果。
- 发布：CI 安装包名包含 r 内部构建号，校验 Android/Windows 版本及构建号一致；相同资产仅接受摘要完全一致的重试。先确认安装包上传摘要，再替换签名清单；拒绝更新入口回退。原本的本地发布 CLI 保留。
- 依赖：更新 shell-quote、source-map-js、http-cache-semantics、xcode 的 uuid，以及 global-agent 依赖链；新增 Undici 与 Media3 OkHttp 数据源，许可原文与组件表已补齐。

已执行的检查：桌面 TypeScript/Vite 编译、Android Web 编译与 Capacitor 同步、Android `compileDebugJavaWithJavac` 成功；官方 npm registry 的完整 `npm audit` 返回 0 个已知漏洞。编译仍有既有的 Vite 大 chunk、Gradle flatDir/弃用 API 提示。

待运行验收：高压缩比输入、DNS 变化及重定向/HLS 私网请求、连续快速切歌/暂停、换源位置、随机单轮终止、磁盘写满/重启后的配置、旧漫游记录迁移和长期去重、缓存清理并发、本地检索、同 tag 的 CI 重试与实际自动更新。当前没有运行自动化测试、真机验收、内存基准或发布流水线，没有生成/上传新的稳定安装包。

## 第二轮复核与外部报告采纳（2026-10-07）

参考用户提供的《当前项目的review结果和改进方案》，逐项对照维护代码，而不是将报告结论直接当作验收结果。

### 已补充的实现

- Windows 源 preload 在 IPC 前检查深度、节点、字节预算和网络并发；二进制消息使用 Uint8Array，避免逐字节转 JSON 数组。源任务和网络各限制 8 个并发，解压全局最多 2 个且同一源最多 1 个，保留全局内存上限。
- 同时进行的源操作使用独立活动 runner；取消搜索/播放只销毁所属 runner，闲置 runner 可复用，窗口退出统一关闭。Android 不再复用已取消关闭的脚本引擎。
- DNS 查询的并发槽位持有至实际查询结束，调用方超时不会提前释放底层查询槽位；303 重定向保留 HEAD。歌词、封面和源文件使用有界文件读取，文件在读取中增长也不能突破预算。
- Android 封面经过原生 DNS/重定向检查后缓存为本地栅格图片；界面仅加载原生返回的本地封面，按可见区域请求并合并相同歌曲请求。图片网络下载不持有音乐源全局播放锁，通知栏使用文件 URI。缓存清理覆盖封面与歌词。
- Android 缓存地址映射剔除已淘汰音频，最多保留 300 项；这是映射索引限制，不删除歌单或历史。超出映射范围的旧音频可能需要重新在线解析。漫游搜索关键词内存最多 512 项，终身歌曲去重仍保存在持久化索引。
- Windows 元数据缓存读取、写入、清理失败产生可见状态，不再把权限错误当作空目录。清理失败暂停写入，后续清理可重试恢复。
- 发布 helper 区分稳定版与预览版，拒绝覆盖到另一发布通道；写入更新清单前验证平台构建号与摘要不倒退，并处理并行提交更新清单的冲突。此 helper 只做静态检查，没有实际上传。
- 采纳报告的 Android 超限消息立即报错建议：结果、HTTP 桥消息超限或损坏时关闭对应脚本引擎，避免只等待超时。
- 平台目录转换集中到 `scripts/Portable-Catalog.mjs`；关键替换必须恰好命中一次，否则构建失败。原生响应长度在 ArrayBuffer 拷贝前检查，已知封面目录端点改为 HTTPS。
- Android 完整展示快照改到专用后台执行器生成，合并重复请求；普通播放更新只发送动态状态。PrivateStore 不再为每次磁盘保存额外深拷贝整份 JSON；快照仅读取所需字段。750 ms 播放进度更新此前已经是部分状态，本轮没有将该部分重复认定为全量拷贝。
- `docs/ios.md` 增加恢复发行前的网络、权限、桥接、签名与验收准入清单；iOS 保持暂停发行。

### 外部报告建议的处理状态

1. 用户已明确批准完整回归验证。过期 aria-label 断言已按“查看贴纸、显式点击才播放”的产品行为更新，原有 32 项回归通过；随后补充安全边界、加密迁移、缓存失败、音乐条手势与真实 Electron 整页测试。最新完整结果见下节。
2. Windows/Android 新增独立的逐源 HTTP 开关与可选域名范围，安装确认页和已安装源设置都可修改。新源默认 HTTPS，旧配置保留已使用的 HTTP 兼容授权。域名为空表示可访问经过校验的公网域名，空数组表示不允许域名；不是根据首次请求自动授权。每次实际请求和重定向都校验，HTTPS 不允许降级重定向到 HTTP。本机、私网、特殊地址与 IPv6 隧道地址拒绝访问，声明 localhost 也不能绕过。完整 Zenix 源仍使用清单声明的 HTTPS 域名。
3. Windows 音乐源索引与设置改为 Electron 系统加密；Android 私有状态文件改为 Keystore AES-GCM。旧明文读取成功后原子迁移；解密、结构校验或迁移失败保留原文件并拒绝后续写入。没有明文保存兜底。脚本文件仍是源码，脚本内常量、内存中的授权值以及源执行时可读的设置不因此受到静态加密保护；同一用户下恶意程序也不属于这项加密能防止的威胁。
4. 目录协议中的设备标识和摘要常量属于兼容协议参数，已集中并注明用途；不能未经上游协议验证就将其替换为随机值。本轮不将它们宣称为用户凭据，也不宣称因此完成全部网络策略。
