## 已确认问题与最小修复

### F1 · P1：Android 设置保存与后台写盘可能死锁

- 位置：`SpaceFeatureCommands.invoke(save)`、`PlaybackService.playbackFeature(preferencesSave)`，关联 `PrivateStore.flush / backupLocked / replaceAtomic`。
- 触发：设置命令先持有 store 状态锁，再调用 `set` 等待磁盘锁；后台 flush 已持有磁盘锁，准备读取状态时又等待 store 锁。设置命令位于主线程，可能导致界面和后续命令停住。
- 二次核实：隔离 JVM 使用实际 PrivateStore 的锁，控制两个线程的交错；基线空间保存明确复现死锁。测试复制基线源码到诊断目录，没有回滚工作区。
- 修复：两处采用 `backupLocked` 的磁盘锁 → 状态锁顺序；冲突核验和 `replaceAtomic` 在同一临界区。写盘失败不提前替换内存中的设置，不迁移资料、不改变格式。
- 复核：空间保存和实际播放偏好保存分支均执行并发用例；旧 revision / expected 被拒绝；模拟落盘失败后内存与原文件保留；重新打开存储后喜欢、源与两类设置保留。JVM 不代表 Android Keystore / OEM 真机行为。
- 状态：已修复并验证。

### F2 · P2：已打开的工作台忽略助手后续的栏目请求

- 位置：`FeatureLauncher.FeatureHost` → `FeatureWorkbench`。
- 触发：Workbench 的内部 tab 只在首次挂载时读取 initialTab。助手请求打开任务或设备协作时，宿主虽改了 initialTab，现有工作台仍停在旧栏目；重复请求原栏目时宿主字符串状态也不变化。
- 修复：每次外部打开请求带递增的本地请求序号；现有工作台根据栏目和请求序号更新 tab，不通过重建工作台解决，不重建播放器或资料订阅。
- 复核：桌面与移动桥接下，从手动选择的栏目切到任务、设备协作和原始栏目；相同栏目请求也可重复生效。保留原有布局、皮肤、迟到歌词、导入、关闭及错误恢复断言。
- 状态：已修复并验证。旧代码的同一新增交互断言失败，修复后通过。

### F3 · P2：同步失败清理可能误清另一个入口的新预览

- 位置：`syncTransfer` → `featureHost.mergeSync` → Companion / Android CompanionTools 的 importDiscard。
- 触发：同步拥有预览 A，确认失败或预览被其他入口处理后，另一个入口建立预览 B；原清理调用不带 token，后端会清掉当前的 B。
- 修复：同步适配器从失败处理到 importDiscard 全程传递自己持有的 token。复用后端已有所有权检查，拒绝清理 B，不修改导入格式或权限契约。
- 复核：在 PC 和移动 host 包装入口分别注入确认失败及后来预览；清理请求仍指向 A，后端拒绝后 B 保留，个人歌单不变。基线调用缺少 token，新增用例失败。
- 状态：已修复并验证。

### F4 · P2：从更新提醒启动下载后无法在该弹窗取消

- 位置：`UpdateNotice` 的 downloading 按钮。
- 触发：下载 action 等待整个原生下载 Promise，busy 持续为 true；取消按钮也被同一个 busy 禁用，直到下载结束才能点击。设置页原有取消入口没有此限制。
- 修复：下载中允许点击取消按钮，继续走已有原生 cancel；安装和其他主要动作的忙碌控制保留。
- 复核：真实 React / Electron 隔离界面中保持下载 Promise 未完成，确认取消按钮可点击、cancel 到达桥接、下载结束并显示取消结果；保留提醒关闭、安装前确认和后续版本展示的原断言。旧代码明确失败于 disabled=true。
- 状态：已修复并验证。没有改变下载、校验、安装或资料保留协议。
