# v1.0.4 / r50 审查记录

2026-10-19，基于 v1.0.3/r49 维护后的 main。按用户最终范围，只新增文本导入，不增加汽水或 LX 专用解析；包含此前本地完成的手机贴纸双指缩放。

## 范围与结论

本轮检查全部新增、修改文件和新文件，并核对 PC / Android 的导入预览与确认、歌单存储、自动平替三次预算、取消、普通播放搜索、缓存、音乐空间手势、原生桥接和分享输入。全项目核心链路复核沿既有生产实现及自动回归覆盖播放、队列和漫游、资料备份恢复、音源权限、更新检查下载校验与 Windows 安装器兼容；不声称历史所有文件逐行无缺陷。iOS 不在本轮打包范围。

已处理的确定问题：

- 文本表头识别如果用于每一行，会跳过名为 `Name` 等与表头相似的真实歌曲；现只识别首条有效记录的表头。编号识别要求英文句点后有空白，避免损坏 `2.0` 这样的歌名。
- 分享读取请求可能晚于用户查看或忽略动作返回，导致旧分享再次出现；现按分享 token 忽略已消费回执。原生端也拒绝旧 token 清掉后来收到的分享。
- 仅有歌名、歌手的文本没有平台播放 ID 或时长，不能套用完整歌曲严格元数据比较。导入用独立元数据标识，默认开启歌单自动匹配并在两端持久保存；从喜欢等入口直接播放时，仅对该标识按完整歌名和已填写歌手匹配，不放宽普通歌曲的去重标准。

新建歌单保留原始歌名、歌手和顺序，同名歌单加后缀，不覆盖原歌单；自动匹配保留已有前三候选、状态等待、显式失败后继续和取消机制。纯歌名的版本歧义在导入界面说明。解析和文件读取不写资料，只有用户确认导入才保存。不复制账号、授权、音频或文件路径。

## 验证边界

本地验证包含生产保存与重新读取、元数据导入到真实自动平替适配器的调用、最多三个候选、UTF-8/CSV/TSV/错误格式、原生分享 token 与长度边界、跨端交换策略保留，以及真实 Chromium 中的电脑文件选择调用、手机文本导入、窄屏布局和双指触摸事件。

按用户本轮明确要求，不连接手机，不操作正在使用的桌面应用，不执行实际设备覆盖安装或人工体验验收。更新兼容性以原发行身份、递增构建、真实新工件、签名清单和旧生产检查器的本地自动核对为范围，不将其表述为本次实机完整升级通过。历史 r49 的实际升级证据仍仅证明当时工件。实际新签名清单交由旧 Android 生产检查方法进行 96 例核对，旧 Windows 生产检查器进行 14 例核对，全部通过；这些仍是本地自动验证。

本轮全套自动回归 164/164 通过（零失败、零跳过）；审查修正后受影响的导入与电脑文件交互路径 20/20 通过，随后补充的文本普通播放入口核对所在解析测试 12/12 通过。上述测试范围有重叠，不合计为独立案例总数。两端最终构建通过，APK 与实际旧 r49 的原证书、包名以及构建身份一致性检查通过；Windows 安装器内实际 app.asar 与版本、配置核对通过，两端包内资源分别与构建输出逐字节摘要一致。Windows 保持原 `signed-manifest` 信任模式；不新增或伪称存在 Authenticode 发行证书。Android 沿用原正式密钥和包名，旧安装包与固定更新入口保留。

后续最值得根据反馈改进的是文本格式识别：收集用户实际清单样例并增加针对性识别规则，避免靠猜测交换歌名和歌手。若需要提高纯歌名匹配准确性，应优先补充歌手信息；本轮没有宣称全部歌曲必定可播放。
