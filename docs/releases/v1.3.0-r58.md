# Zenix v1.3.0 · r58 维护更新

> 最新维护修订为 [r59](v1.3.0-r59.md)。下文保留 r58 的发行记录。

修复 PC 和 Android 下载更新时，仍在传输却被整次十分钟上限中断、随后丢弃已下载进度的问题。

- 有有效传输进度就继续下载，不再因总时长超过十分钟中断。
- 保留连接、连续无读取进展保护和主动取消；不把无限等待当成功。
- 网络中断或取消后保留同一安装包的有效部分，重试使用严格核对的 Range 续传。服务器不支持续传时从零重下，不能把完整响应追加到旧文件。
- 安装前仍验证完整大小、SHA256、原发行身份；Android 包名和原证书不变。校验失败的内容不会安装。

公开版本仍为 **1.3.0**，双端内部构建递增为 **58**。保留现有歌单、喜欢、收藏、配置及旧包下载地址，不要求卸载或清空资料。新工件以 `r58` 命名，作为同一个 v1.3.0 Release 的维护修订加入，不覆盖 r57 字节。

兼容边界：新清单可以让旧版发现 r58，但不能改写旧客户端已经固化的十分钟限制。先成功安装 r58 后，后续下载才使用新的等待与续传逻辑。不承诺旧版在任意慢网络下首次下载均能完成，也不把版本上下文模拟当作真实覆盖安装。

必要验证覆盖持续进度、无进度、取消、断线续传、200／206／416、异常范围、损坏文件、完整文件复用及原更新签名／安装门禁；双端实际包另核对版本、构建、更新配置和原 APK 证书。没有操作在用客户端资料或执行实机安装；用户层面测试按既有完成约定跳过。

本次修复不改变音乐源解析、播放重试、贴纸展示或角色皮肤。


本地必要自动测试 **36/36 通过**，涵盖下载状态、续传协议、原更新管线、发行契约和资料保护。Windows NSIS、Android Web 与正式 Gradle 构建完成，实际 Windows 包内两个更新模块与源码字节一致；实际 APK 与既有 r57 包均通过原发行证书和内置更新配置核验。
