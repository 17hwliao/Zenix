# 移动端播放与歌曲手势优化

2026-10-08，该功能首次完成于开发构建 17，公共版本仍为 1.0.0。后续用户授权将 build 16 / 17 功能随 r18 正式发行，另增加 [移动界面修补](mobile-ui-r18.md)。build 17 Debug 预览仅供开发，iOS 继续暂停发行。

## 后台加载与操作

播放解析、跨源歌曲匹配与浏览请求分别持有自己的脚本运行实例。搜索、封面、歌词不再占用正在解析播放的实例；取消播放只关闭播放侧请求。后台清理仅释放空闲实例，不关闭正在执行的请求。

解析时先显示原生前台通知，并申请最长 45 秒的短时 CPU 唤醒保护；播放准备完成、失败或明确停止时释放保护。前台通知提供“停止加载”，正常播放后交回 Media3 的媒体通知。喜欢、收藏、歌单和统计写入也与封面 / 歌词网络工作分开，避免保存操作排在慢速资料下载之后。

播放状态增加 `playWhenReady`。正在加载时按钮显示“暂停”，明确点暂停仍会停止当前加载；浏览页面、查看歌单、长按保存不改变播放意图。播放和漫游命令返回的局部快照按字段合并，保留个人歌单与音源状态，避免用局部响应替换全部界面数据。

原生服务与前台通知改善后台存续，但不能保证系统强制停止、断网或厂商省电限制下继续加载。设备验收见末尾。

## 左右滑动移出歌曲

- 在“当前播放列表”中，向左或向右滑动歌曲行即可移出当前队列，也保留显式移出按钮。
- 自定义歌单、喜欢和收藏的音乐空间增加“管理歌单歌曲”按钮；进入列表后，可以左右滑动移出对应列表。
- 移出自定义歌单不会同时删除当前队列、其他歌单或音频文件；移出队列也不会删除个人歌单。移出正在播放的队列歌曲会沿用原生队列规则，切到下一首，队列为空时停止。
- 横向有效滑动阈值为 72 像素；短滑、纵向滚动和取消手势不删除。滑动和长按会消耗随后产生的点击，避免误触播放。

操作消息不拦截触控。弹层重新打开时恢复触控，避免快速关闭再打开后只能看到内容却不能操作。

## 长按快捷保存与动画

长按歌曲行、歌曲贴纸、底部当前歌曲区域或完整播放器的歌曲区域，可以打开“快捷保存”：加入喜欢、加入收藏、同时加入喜欢和收藏，或加入歌单。

快捷保存为幂等添加：重复点击同一个歌曲不会取消已有喜欢 / 收藏，不重复插入歌曲。既有心形、星形按钮仍支持切换选中状态。

保存成功后显示心形 / 星形弹出、光环和小粒子动画，采用现有的开源 [Motion](https://github.com/motiondivision/motion/blob/main/LICENSE.md) 与 [Lucide](https://lucide.dev/license)。没有添加新的动画下载依赖；素材由组件绘制，减少动态效果偏好开启时省略粒子和缩放。

## 缓存是否真实播放

Android 已使用 Media3 `SimpleCache` 将播放读取的音频字节写入磁盘，并按用户设置的上限清理。已有实现的问题是：只有整首缓存完整时才跳过音乐源解析，因此“播放过一次”但只缓存了部分片段，重新打开仍会解析。

本轮明确区分以下状态：

| 界面状态 | 含义及重复播放行为 |
| --- | --- |
| 完整缓存 · 可离线 | 已知音频长度，且从头到尾的字节均在缓存中。直接使用缓存，不调用音源解析；音频解码仍可能有短暂准备过程。 |
| 部分缓存 | 只有部分字节可复用。已有至少 64 KiB 的开头且解析地址保存不超过 10 分钟时，先使用该地址及缓存片段，剩余数据联网获取；过期或请求失败时重新解析。 |
| 流式音频 | HLS 等流式资源暂不保证整首离线，不能显示为完整缓存歌曲。 |
| 缓存已关闭 / 本地音频 | 分别遵循缓存开关或直接读取用户导入的音频。 |

底部播放条和完整播放器会显示当前缓存状态。完整缓存路径限制上游网络；部分缓存复用重新校验当前音源的网络策略。缓存被容量清理或系统清除后，需要重新联网获取。缓存保存在应用缓存目录，不等同于永久下载文件。

仅听一段、拖到末尾或音频大于缓存预算都不一定得到整首缓存。不能仅凭“加载中”判断是否命中缓存，也不应把“已播放”直接标为“已离线保存”。

## 音源顺序与等待

Android 优先尝试最近实际播放成功的源，然后是歌曲原始源，再按用户顺序回退。音乐源管理增加上移、下移，顺序保存在本机，不根据私人脚本名称猜测优劣。

每个源的初始化、歌曲匹配和音质解析共用约 10 秒预算；一次解析总体预算约 30 秒。取消和超时都会停止对应的脚本网络请求。网络连接失败、超时、服务端异常或限流后，临时跳过该源约 60 秒；如果所有源都在冷却中，仍允许用户重试。

单档音质不可用时继续尝试下一档；连接问题不再重复等待同一源的所有音质。媒体解码错误仍允许同一源降级音质，媒体网络错误才进入源冷却。提示中显示尝试序号和总数。等待上限针对解析任务，后续真实网络传输与解码耗时不能视为已保证的起播时长。

## 验证范围

生产 `MusicSources`、请求实例管理、优先级、缓存决策和快捷保存代码直接编译并在 JVM 执行；Android 平台、脚本引擎与 HTTP 为合约测试替身，未接触私人音源。

真实 Electron 中渲染完整 React 移动界面，使用实际鼠标指针事件验证左右滑动、长按、动画和不误触播放；包含局部原生响应的合并验证。列表在 320 / 360 / 390 / 430 宽度无横向溢出。截图及完整回归输出保存在 `release/regression/`。

本轮完整回归、桌面 / Android Web 构建及原生 Debug 构建的具体结果记录在 `PROJECT_STATE.md`；预览工件位于 `release/feature-preview-build17/`。Android Debug 包不能覆盖已有正式签名版本。

仍需 Android 真机验证：加载时切后台 / 锁屏、真实触摸与输入法、实际音源成功率和起播耗时、断网后完整缓存的实际声音输出，以及不同厂商省电策略。JVM 和桌面 WebView 验证不能替代这些设备验收，没有新的峰值内存或真机耗时承诺。

原生后台设计参考 [Android Media3 后台播放文档](https://developer.android.com/media/media3/session/background-playback)。
