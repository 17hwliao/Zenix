# 个人 K 歌：伴奏、曲谱与练唱评分

桌面和 Android 的个人练唱使用同一个页面；局域网对战保留独立房间、网络协议和评分契约。用户选歌后自动并行准备伴奏和曲谱，不需要先逐项点击搜索。本轮交付是本地验收，不改版本号、签名、发行身份或更新通道。

## 音轨与曲谱

- 选择歌曲后，自动准备按“已确认配对 → 已生成的本地分离缓存 → 已启用的音乐源”依次复用或查询。音乐源只接受明确标为伴奏且歌名相符的候选；同名、歌手和时长相近仍不能证明是同一录音，因此歧义候选必须试听并显式确认。用户也可手动搜索或导入 MP3、WAV、FLAC 等文件。
- 有伴奏时默认使用伴奏。原声用于试听和对照，来回切换沿用媒体时钟，异步切换失败时尝试恢复原音轨。没有伴奏时，界面只能“试听原声”，不会把商业录音显示为无人声。PC 可显式使用本机 Demucs 与 torchcrepe 生成待核对资源；Zenix 不联网下载或自动执行模型，Android 不提供该入口。
- 网络搜索没有伴奏且原曲存在本地文件或完整缓存时，桌面端才检查本地 Demucs 4.0.1、固定模型摘要与磁盘条件；已有分离缓存先直接复用，Android 不提供生成入口。分离生成的伴奏必须与原曲的实际录音身份和时长一致，并通过真实播放验证后才会绑定。
- 曲谱支持传统 UltraStar 单人轨、MIDI 和带音高的增强 LRC。开放曲谱搜索为限定目录，当前收录 UltraStar 项目中三份已核对许可证的曲谱。下载固定版本、限定大小、核对 Git 文件指纹，不下载音频或执行谱面内的其他资源指令。也可从完整上游目录按其许可证手动取用。相同标题和歌手也不证明同一编辑版本。
- 进拍线和音高块来自曲谱。普通 LRC 可显示和跟读，不用于虚构音高。双人曲谱不用于个人评分。
- 伴奏和曲谱是两条独立状态。伴奏就绪但曲谱缺失、待确认或查询失败时仍可跟唱，主按钮明确显示“开始演唱 · 暂不计分”；只有伴奏、曲谱和当前录音的时间轴都绑定成功，本轮才启用评分。

## 评分与记录

- 在伴奏模式下，麦克风仅在本机生成音高样本；切到原声暂停采分。每句按音准、节奏、完成度分别评估，权重为 60%、25%、15%。有正常采样却没唱是漏唱；没有有效采样区间是未评估。
- 每句完成后显示分数。完整一轮的总分按所有歌词句等权平均；未唱完整或有未评估句时显示已唱句平均分和覆盖句数，不当成全曲成绩。结果显示音准、节奏、完成度以及前、中、后段评价，包含逐句反馈。
- 练唱记录存于当前客户端的 IndexedDB，可继续展开历史记录。保存内容为时间、歌曲名称及评分摘要和逐句反馈，不含原始麦克风录音、音源地址或音高帧。本轮没有加入跨设备同步。伴奏文件和当前曲谱只用于当前选曲，重新进入可以再次导入；评分记录不依赖原资产仍可用。曲谱已通过内容与时间轴校验但 IndexedDB 写入失败时，本轮仍可评分，界面明确提示“本轮可用但未保存”。

## 来源及产品边界

- [DAM 导唱功能](https://www.clubdam.com/faq/ps4/function/guide_vocal.html)：产品资料公开区分伴奏和导唱；不推断其各型号商用设备的内部实现。
- [UltraStar Deluxe 传统实现](https://github.com/UltraStar-Deluxe/USDX/blob/master/src/base/USong.pas)、[UltraStar 格式](https://github.com/UltraStar-Deluxe/format)、[逐曲授权的数据目录](https://github.com/UltraStar-Deluxe/songs)：相对音高和节拍位置来自标准，曲谱授权与软件开源许可独立。
- [Demucs](https://github.com/facebookresearch/demucs)：本地人声与伴奏分离的开源参考；上游项目已归档。当前不下载其模型，也不将简单左右声道抵消宣称为智能分离。

## 本地伴奏与曲谱生成计划（2026-11-24）

本节记录已落地的本地生成链路和剩余验收边界。实现只存在于当前 `feat/ui-refresh-karaoke` 工作树，不改变版本号、发行身份或更新通道。

截至 2026-11-24，已完成受控类型与 IPC、歌词快照、Demucs 双轨验证、伴奏先发布、torchcrepe 曲谱 worker、sidecar 缓存、取消与进程树终止、前端生成状态及待确认草稿接线。隔离探针已真实完成 12 秒合成音频的 Demucs 分离和 torchcrepe 音高推理；完整 runtime 作业也在 175 秒内返回 4 个音符、3 个有效歌词行的 `ready` 结果，产物通过现有 `validatePreparedChart`。真实用户歌曲质量、1000/390/320 像素视觉验收和 Android 实机仍待验证。

### 目标与边界

用户在「伴奏与音高」中可以选择「从原曲生成」。PC 从已导入或已完整缓存的原曲生成本地伴奏，并在已有歌词和音高分析条件满足时生成待核对的 UltraStar 曲谱。伴奏与曲谱继续作为两条独立结果，伴奏就绪即可跟唱，曲谱确认后才启用评分。

首版只处理以下输入：

- 原曲必须来自本地音乐库，或已有通过身份检查的完整音频缓存。
- 用户必须明确点击生成，不把后台分离作为自动扫描或上传服务。
- 曲谱草稿优先使用当前歌曲已有的逐句时间歌词。普通 LRC 只提供歌词行时间，不凭空声称逐字对齐。
- Android 不运行 Demucs、CREPE 或 SOFA，只读取 PC 生成并在本机确认过的伴奏与曲谱，或继续使用原有导入和搜索入口。

首版不自动下载或执行来路不明的模型权重，不接受网页搜索结果直接作为本地曲谱，不修改普通播放器队列、已确认音源配对或发行身份，也不取代现有的外部伴奏试听确认规则。

### 生成流程

```text
选定原曲
  → 解析本机路径或完整缓存
  → Demucs 分离 vocals / no_vocals
  → 发布并验证伴奏缓存
  → CREPE 分析 vocals 音高
  → 使用已有逐句歌词建立时间边界
  → 合并音高段并生成 UltraStar 草稿
  → Zenix 现有曲谱解析与时间轴校验
  → 用户试听、确认
  → 本轮或下一轮启用评分
```

Demucs 产物是「本地分离」伴奏。CREPE 产物是算法草稿，界面必须标记「待核对」。两者都不冒充授权官方伴奏或人工编校曲谱。

### 组件与接口

| 层 | 设计 |
| --- | --- |
| Electron IPC | 保留现有 `karaokeSeparation` 的查找、检查、生成和取消语义。新增受控生图请求，只接受歌曲标识、当前请求标识、歌词快照和生成选项，不接受渲染器提供的本地路径或 shell 参数。 |
| 作业代理 | 继续由 `KaraokeSeparation` 独占 Demucs 进程和伴奏缓存。增加一个可选的同作业曲谱阶段，伴奏验证成功后先发布，再分析人声。曲谱阶段失败不能撤销已经验证的伴奏。 |
| Python Worker | 新增受控 worker，接收主进程指定的 `vocals.wav`、歌词和时间设置，输出 UltraStar 文本和结构化告警。Worker 不联网、不读取歌曲目录、不拼接 shell 命令。 |
| 曲谱解析 | 复用 `prep-chart.ts` 的标题、歌手、总时长和音符范围校验，以及 `discoverChart`、`confirmPreparedChart`。生成曲谱使用同一确认与 IndexedDB 持久化入口。 |
| 前端控制器 | `prep-controller.ts` 增加生成状态、取消、重试和迟到结果隔离，并接收 `readLyrics`。伴奏状态与曲谱状态独立更新。 |
| 界面 | `KaraokePanel.tsx` 在无可用伴奏时提供「从原曲生成」。生成过程中显示当前步骤，完成后把曲谱放入现有核对区。窄屏保持主操作可见。 |

建议的返回契约：

```ts
type LocalGenerationResult =
  | { status: 'generating'; stage: 'separating' | 'publishing' | 'pitching' | 'aligning' | 'validating' }
  | { status: 'ready'; backing: KaraokeSeparationArtifact; chart?: GeneratedChartDraft; message?: string }
  | { status: 'partial'; backing: KaraokeSeparationArtifact; chartFailure: string }
  | { status: 'unavailable'; reason: 'dependency' | 'model' | 'lyrics' | 'input' | 'disk' | 'busy'; message: string }
  | { status: 'cancelled' };
```

`chart` 只表示可解析的草稿，不表示已经确认。曲谱草稿至少携带生成模型、参数版本、歌词来源、时间轴告警和内容 SHA-256。真正可用于评分的数据仍由 `validatePreparedChart` 与用户确认产生。

### 开发步骤

#### 1. 技术探针与许可门禁

- 使用一段 10 至 20 秒的有歌词中文或英文片段，分别验证 Demucs、CREPE 和歌词对齐输出。
- 固定 Python、PyTorch、torchaudio、librosa、torchcrepe 与模型的精确版本，记录 CPU 耗时、峰值内存、临时磁盘和输出大小。
- 核对代码许可和实际下载的权重许可。Demucs、CREPE 和 SOFA 仓库均为 MIT，但 SOFA 及其他运行时权重的再分发条件必须按实际文件确认。[Demucs 许可](https://github.com/facebookresearch/demucs/blob/main/LICENSE) [CREPE 许可](https://github.com/marl/crepe/blob/master/LICENSE) [SOFA 许可](https://github.com/qiuqiao/SOFA/blob/main/LICENSE)
- 将 USKMaker 作为流程参考。其 MIT 源码使用 Demucs、歌词强制对齐、音高提取和 UltraStar 导出，默认对齐权重属于 CC BY-NC 4.0，不能直接作为 Zenix 商用发行依赖。[USKMaker 文档](https://github.com/walterfr/UltraStarKaraokeMaker/blob/main/README.en.md)

完成标准：不依赖网络推理即可生成可被 Zenix 解析的 UltraStar 草稿；模型来源、摘要和许可可追溯；依赖缺失时给出准确原因。

#### 2. 类型、IPC 与受控作业

- 定义生成请求、阶段事件、部分成功结果和错误代码。
- 更新 `src/core/types.ts`、`electron/preload.cjs`、`electron/main.cjs`，主进程从 `Track` 重新解析受信任路径，渲染器不获得原生路径写入能力。
- 复用现有单任务、取消、超时、进程树终止、来源文件哈希和磁盘预算门禁。
- 保留现有分离 API 和测试，先证明旧调用方行为不变。

完成标准：同一时刻只运行一个本地生成任务；取消、切歌和关闭应用都能终止子进程并清理临时目录；旧分离入口回归通过。

#### 3. 伴奏先发布、曲谱可部分成功

- 在 Demucs 作业中同时验证 `no_vocals.wav` 和 `vocals.wav` 的 WAV 格式、采样参数与时长。
- 伴奏通过验证后立即进入现有伴奏缓存，保留相同的渲染器媒体协议和时长校验。
- `vocals.wav` 只存在于受控临时目录，曲谱完成或任务结束后删除。首版不把原始人声持久化到普通缓存。
- 曲谱失败返回 `partial`，界面继续开放伴奏试听，不把整次生成判为失败。

完成标准：伴奏缓存可跨重启复用；不同原曲不串用；生成失败和取消不留下可命中的半成品。

#### 4. 生成首版逐句音高谱

- 从当前歌曲已有歌词取得带开始时间的行。对于 LRC，使用相邻行开始时间建立句段边界并修正零长度和重叠区间。
- 对分离人声运行 CREPE。过滤低置信度、低能量和异常八度片段，将连续稳定帧合并成音符。
- 按歌词句裁剪音符，保证开始和结束都在原曲与伴奏共同时间轴内。
- 估计节拍并量化到 UltraStar tick。估算不可信时使用明确标记的固定 BPM 回退，不使用伪造的逐字边界。
- 输出标题、歌手、BPM、GAP、逐句音符和 `E` 终止行。生成后的文件必须重新经过 Zenix 自身 UltraStar 解析，而不是只检查字符串格式。
- 草稿附上「自动生成」「歌词来源」「节拍回退」「可信句数」和告警行，界面不把这些提示藏到调试信息里。

完成标准：至少一首带逐句时间歌词的样例可以产生非空音高谱，结构校验通过；没有音符或时间超出原曲时拒绝草稿；普通 LRC 不会被误报为精确音高谱。

#### 5. 控制器和界面接线

- 从 `KaraokePanel` 把现有 `readLyrics` 传入准备控制器，并在点击生成时取得一份歌词快照。
- 生成按钮只在 PC、原曲可访问、依赖可检查时出现。已有外部伴奏候选时仍可单独选择生成，不从候选列表自动挑一首。
- 增加状态「准备本机分析」「分离伴奏」「发布伴奏」「提取音高」「生成曲谱」「核对曲谱」，支持取消和单项重试。
- 伴奏完成后沿用现有试听、确认和切换入口。曲谱草稿直接进入现有 `draft` 核对区，显示开头几句、告警和「确认曲谱与伴奏对齐」。
- 换歌、关闭个人练唱或开始演唱后，旧生成的迟到结果不得替换当前歌曲。正在演唱时完成的曲谱只留到下一轮，当前轮沿用开唱时冻结的评分依据。

完成标准：1000、390 和 320 像素宽度下主操作可见；无依赖、无歌词、部分成功、取消、查询失败和曲谱确认失败都有可恢复入口；现有伴奏搜索与开放曲谱入口不受影响。

#### 6. 歌词对齐增强

在首版逐句曲谱通过验收后，再接入 SOFA 处理普通无时间歌词。保留 `chart-v1` 与 `chart-v2` 参数版本，新增对齐模型不能让旧缓存被错误解释。

若需要覆盖用户没有提供歌词的歌曲，再评估 WhisperX、faster-whisper 或其他本地转写方案。该能力单独设模型下载、语言识别、中文分词和校对验收，不阻塞首版「从原曲生成伴奏」。

完成标准：无时间歌词可以被对齐成待核对曲谱；对齐失败时明确回退到仅生成伴奏；不同对齐模型和歌词版本不会复用错误曲谱。

#### 7. 测试、Review 与本地验收

自动测试至少覆盖：

- 内容去重、模型版本、参数版本和跨歌曲缓存隔离。
- WAV 时长不一致、输出损坏、模型摘要不符、磁盘不足和依赖缺失。
- 取消后子进程、临时目录和媒体地址释放。
- 快速换歌、重复点击、旧响应返回和开始演唱后的迟到曲谱。
- 歌词边界、重叠、超长句、普通 LRC、中文无空格和零音符。
- UltraStar 生成后再解析、标题歌手一致、音符时间范围、节拍回退标记和文件大小限制。
- 只有伴奏的部分成功、曲谱确认成功与保存失败。
- Electron 受控路径、IPC 参数校验和旧 `karaokeSeparation` 回归。

验收使用隔离资料和本地样例音频，覆盖以下路径：

1. 无匹配伴奏和曲谱的原曲生成伴奏与曲谱草稿。
2. 伴奏在曲谱失败时仍可试听、确认和跟唱。
3. 生成曲谱经过核对后完成一次逐句评分。
4. 再次进入同一原曲时命中已验证伴奏，曲谱按歌词和模型版本复用。
5. 取消、退出和换歌后没有残留进程或临时媒体地址。

完成后按阶段 Review 检查本阶段改动及调用边界。只完成自动测试或编译不算真实模型验收，实际模型推理、中文谱面质量和 Android 实机分别记录证据。

**KTV-06**：worktree 的 `node_modules` 是 junction，Capacitor 8 会把它解析成源 checkout 路径并写入 `android/capacitor.settings.gradle`。后续 Android 构建因此读错依赖。现于每次 `cap sync android` 后执行幂等路径修复，测试同时锁定“先同步、后修复”的顺序。

**KTV-07**：Python 曲谱 worker 已包含进 Electron 文件清单并加入 ASAR 解包，但此前缺少打包态回归。现已验证 Windows 目录包中的 `app.asar.unpacked/electron/runtime/karaoke-chart-worker.py` 与源文件同为 28,118 字节、SHA-256 相同；`app.asar` 中只有指向该解包位置的索引，实际文件由 `app.asar.unpacked` 承载。

**KTV-08**：损坏的曲谱 sidecar 会被读取逻辑忽略，但旧写入逻辑无法替换损坏 JSON，导致之后每次都要重新生成草稿且仍写不回缓存。现把“无法解析”视为可替换状态，并用真实重生成测试确认新草稿恢复缓存。

**KTV-09**：若本机分析依赖忽略取消信号，退出流程可能永久等待。关闭现在保留正常子进程终止与清理等待，并增加 5 秒故障宽限，避免异常依赖阻止应用退出。

**KTV-10**：空间展示引导的临时关闭状态原先不会在受控 `open` 从关闭重新变为打开时复位。现于引导关闭阶段复位，并用桌面沉浸模式进入、退出的真实组件测试确认引导重新出现。
