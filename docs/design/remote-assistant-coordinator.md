# 远程音乐助手：会话和执行协调

本轮仅本地开发与受控测试，不调用真实付费模型，不操作用户主资料，不制作安装器或发布。

## 所有权与入口

每个实际客户端由应用生命周期持有一个 `AssistantCoordinator`。对话框、角色、文字和语音只订阅 `getSnapshot` / `subscribe`，发送 `submit`、`confirm`、`chooseCandidate`、`cancel` 与 `setListening`。工作台固定快捷按钮通过 submit 的可信 local 模式使用同一协调器，保留片段标记等既有本地功能，不额外请求模型。该模式不是模型工具参数。收起面板不销毁协调器、不撤销已提交操作。运行时负责模型配置事件与应用退出清理。

协调器不实现播放器、歌单存储或 HTTP。它只调用唯一注册表派生的模型工具、严格参数校验器、原生 `NativeTransport` 与固定的 `BusinessAdapter`。本地旧指令由注入的 `LocalAssistantHandler` 执行；无 Key、禁用模型、模型传输失败或低识别置信度时仍走既有本地解释器。命名追问由本地解释器持有，取消、改配置和销毁通过 `onLocalReset` 清除。

公开快照区分 `idle`、`listening`、`understanding`、`needs_input`、`awaiting_confirmation`、`executing`、`task_created`、`completed`、`failed`、`cancelled` 与 `unknown`。`ToolResult.status` 仍保留 `saved`、`loading_started`、`playback_started` 等真实业务差别；不能把建立任务或开始加载写成完成。

## 一条请求的边界

1. 客户端生成新的 request ID，退役旧请求和确认票据，终止旧模型网络请求。
2. 加载有限的历史回执，只读取状态核验未确认操作，绝不重放历史修改。
3. 读取本机实际上下文、平台能力和模型配置修订。当前播放、界面选择、打开歌单和搜索候选由业务层分别提供。
4. 每轮从注册表和实际能力生成工具，并在每次工具执行前再次校验参数与能力。工具资料和歌词作为资料传输，不能成为用户指令。
5. 查询结果可供后续工具理解；选择一个修改或确认计划后停止模型续写。每条请求最多提交一个明确业务修改，包括下一首等非幂等播放动作。
6. 业务状态决定结果。没有工具执行时只显示等待补充信息，不把模型叙述视为已保存或已播放。

模型的 `tool_call_id` 只配对协议消息。请求和业务操作另用客户端 ID，重复工具返回、重复确认点击都不能导致二次提交。新的明确用户指令拥有新的业务身份。

## 引用与确认

`SessionReferences` 只发行当前会话的不可猜造引用，区分歌曲、歌单、候选和设备。入库及读取均复制对象；引用具有十五分钟寿命，最多 512 项，超限淘汰最早引用。新搜索清除上一批候选及相应查询缓存，不能拿旧候选播放。

确认计划由可信业务适配器固定目标、项目、数量和验证指纹，协调器生成本机确认票据；计划最多保留五分钟。只有真实界面票据，或置信度不低于 0.62 的既有明确语音确认，才能提交。新指令、取消、改配置、到期、目标冲突都会使旧入口不可用。确认前复查能力、配置修订和业务 `validate`。切换当前歌曲不会替换计划已经捕获的目标。

本地低置信度确认可能先得到另一个资料确认计划。协调器将其展示为新票据，不把“识别确认”误当作资料修改完成。

## 提交、取消和恢复

修改前先持久化 `submitted` 回执，随后提交业务操作；保存期间取消时不进入业务层。回执只包含客户端请求/操作身份、工具、必要本地恢复描述及短结果，不包含模型配置、API Key、原始对话、歌曲全对象或音频地址。浏览器独立键为 `zenix.assistant.operation-journal.v1`。

确认计划的恢复描述在准备时固定，不能等点击确认后再读取“当前歌曲”。提交后取消仅停止后续步骤，仍等待业务返回并记录真实结果；若已收起界面，结果继续保留。提交抛错时使用只读 `reconcile` 核对，不能重试下一首、创建歌单或提交任务。无法唯一确认时为 `unknown` / `partial`，不宣称成功或失败。

重启不会恢复可执行确认计划、旧引用或原始对话，只读取操作回执。未完成远程操作由 `BusinessAdapter.reconcile(OperationRecovery)` 只读核验；缺少可靠描述的旧本地操作只读取业务状态并保持结果未确认，不能猜测或重放。资料恢复的最终解释由业务适配器提供。

回执最多 128 项；明确完成记录保留一天并去除恢复目标，未确认记录保留七天。存储损坏/不可写时阻止新的助手修改，不以丢弃旧记录来绕过防重保护。远程只读工具以及本地解释器通过 `handle.readOnly` 明确预判为不写入的查询仍可使用；不确定命令、命名续答和确认不享有此例外。现有播放器界面不依赖这个回执存储。

## 限额与等待

上限集中于 `REMOTE_LIMITS`：六轮模型调用，每轮四个工具、每请求十二个工具；用户文字 4000 字符、模型响应 256 KiB、每工具结果 12000 字符、会话 32 条消息、搜索候选十个。历史按完整用户/结果对退役，保留完整的当前 assistant/tool 配对，避免孤立工具消息。

这些限额只约束模型理解和资料体积。协调器没有音乐解析或音频加载超时，不改变播放器既有按状态等待的逻辑。确认和引用寿命不是音频超时。

## 必要测试

`node --test scripts/Test-RemoteAssistantCoordinator.cjs` 使用模拟原生传输、隔离业务对象和内存回执，覆盖引用所属/过期、实际平台工具过滤、协议消息配对与大小、一个修改额度、固定确认目标、低置信度/嵌套确认、重复点击、新指令与配置取消、迟到结果、提交期间取消、收起订阅、无 Key/模型失败的本地回退、新搜索退役候选、重启只核验不重放、扩展失败隔离和长期会话消息上限。

这些测试证明受控时序和契约，不代表真实模型理解、真实手机、付费接口或正式升级验收。
