# 局域网 K歌系统设计

状态：已接入本地开发分支，双端实机验收待完成
适用范围：Zenix PC 与 Android
网络范围：仅局域网，不含公网穿透、账号系统或远程房间

## 1. 本版范围

本次递交包含小伊语音。单人练唱 K歌保留底层评分与音高引擎，但不作为本版对外入口。本版新增功能只做局域网红蓝对战 K歌：

- PC 创建房间并展示局域网 IP、端口、六位房号和可选口令。
- PC 与 Android 粘贴房主邀请（包含地址、公钥和房号），填写昵称，由房主批准。
- 每台设备独立采集麦克风并本地评分，局域网只传控制状态和脱敏分数。
- 两端同步看到一个公共红蓝战况：左侧蓝方、右侧红方，中间为对冲碰撞线。
- 房主统一控制开始、暂停、继续、跳歌、结算和重赛。

v1 明确不做：接唱段落轮换、复杂声部分离、Android 当房主、公网联机、观众弹幕。
v1 的合唱简化为“多人同唱、各自本地评分、按阵营累加”，不承诺声部级独立评分。

## 2. 基线修正

实现前必须把当前功能分支与远端最新主线同步，确认小伊语音提交已经包含在实施基线中。现有 `feat/ui-refresh-karaoke` 基于早期主线，并不包含小伊语音；正式实施时不得沿用旧的本地 `main` 引用作判断。

单人练唱目前已经接入正式 `K歌` 分类。本版需要把该正式入口改为局域网 K歌房间入口，同时保留单人评分引擎作为内部复用模块，并同步更新工作台分类与相关测试。

## 3. 连接与房间流程

房主创建房间后展示：

- 非回环 IPv4 地址，例如 `192.168.1.8`
- WebSocket 端口
- 六位房号
- 可选房间口令
- 复制连接信息按钮

客人加入流程：

1. 粘贴完整邀请，保留地址中的 `#公钥`，再填写昵称和可选口令。
2. 客户端连接房主 WebSocket 服务并发送加入申请。
3. 房主看到申请人、来源地址、昵称和申请时间，批准为蓝方、红方或听众，也可拒绝。
4. 批准后房主下发独立授权令牌，客人收到完整房间快照。

阵营分配规则：

- 房主可手动指定蓝方或红方。
- 自动分配时保证两边人数差不超过 1。
- 听众 `side` 固定为 `none`，不能加入演唱队列或提交分数。
- 房主可在开唱前交换双方阵营，开唱后需要先重置对局。

## 4. 拓扑与职责

采用房主权威模式：

- 房主维护唯一房间状态：成员、阵营、队列、歌曲、倒计时、暂停、公共比分和结算。
- 每个客户端本地运行音高、节奏、歌词、完整度与气息评分。
- 客户端只发送逐句分数摘要，不发送原始麦克风数据、音频地址、令牌或本机路径。
- 房主校验、去重、聚合分数，并通过房间快照的 `revision` 广播结果。
- UI 不单开公共比分事件流，统一从房间快照渲染。

普通播放器、个人歌单、喜欢、收藏和播放队列与该房间完全隔离。

## 5. 状态模型

在现有 `KaraokeMember` 上新增：

```ts
side: 'blue' | 'red' | 'none'
```

在 `KaraokeRoomState` 上新增：

```ts
battle: {
  mode: 'versus'
  itemId?: string
  blueScore: number
  redScore: number
  leadingSide: 'blue' | 'red' | 'tie'
  submittedMembers: string[]
}
```

`blueScore` 与 `redScore` 使用 0–100 的加权个人总分的累加值。碰撞线位置和领先权不单独存储为协议字段，由两端 UI 从两份分数稳定计算：

```ts
blueShare = blueScore / (blueScore + redScore)
balance = blueScore + redScore === 0 ? 0 : blueShare * 2 - 1
```

`balance` 范围 `-1..1`：`-1` 代表全红，`0` 代表持平，`1` 代表全蓝。

## 6. 分数协议

新增 `score.line`：

```ts
{
  itemId: string
  memberId: string
  lineIndex: number
  revision: number
  lineScore: {
    pitch: number | null
    rhythm: number | null
    lyrics: number
    completeness: number
    breath: number
    total: number
    grade: KaraokeGrade
    combo: number
    confidence: number
  }
  clientSentAtMs: number
}
```

校验规则：

- `revision` 必须绑定当前演唱 item，非当前 item 返回结构化错误。
- 数值必须是有限数字，并夹取到 0–100；`confidence` 夹取到 0–1。
- `pitch` 与 `rhythm` 在无可信音高资料时允许 `null`，不得伪造数值。
- 去重键为 `memberId + itemId + lineIndex + revision`。
- 允许乱序到达，按 `lineIndex` 聚合。
- 每个成员使用独立限速桶，避免整首歌分数事件挤占心跳和时钟。
- 新字段必须纳入敏感键扫描，禁止 URI、令牌、路径或原始音频进入 payload。

客人断线时，本地保留未确认的 pending 行；重连后按序号补交，房主幂等去重。超过断线宽限期的行丢弃并标为“未评估”。

## 7. 评级与艺术字

新增等级键与显示文案：

| 分数 | grade | 主提示 | 中文副标题 |
|---|---|---|---|
| 100 | `perfect` | WONDERFUL | 完美天籁 |
| 95–99.9 | `excellent` | PERFECT SHOT | 近乎完美 |
| 90–94.9 | `veryGood` | VERY GOOD | 非常好 |
| 80–89.9 | `good` | GREAT | 表现很棒 |
| 70–79.9 | `nice` | NICE | 状态不错 |
| 60–69.9 | `pass` | KEEP GOING | 继续加油 |
| <60 | `retry` | TRY AGAIN | 再唱一次 |

艺术字组件要求：

- 粗体、单层描边与高光，100 分使用金色强化。
- 入场短促放大回弹，约 700ms 后退场，不遮挡下一句歌词。
- 蓝方提示偏冰蓝，红方提示偏赤红，同时保留文字和图形符号，避免只靠颜色区分。
- `settings.motion === 'reduced'` 时退化为淡入淡出。
- 不使用外部字体或远程资源。

## 8. PC 界面

房主页：

- 左侧固定蓝方演唱者、实时分和连击。
- 中间是公共红蓝对战条，蓝方从左侧推进，红方从右侧推进。
- 右侧固定红方演唱者、实时分和连击。
- 下方为歌词、本机音高曲线和麦克风状态。
- 顶部固定房号、IP、暂停、结束和复制连接信息。

客人页：

- 加入表单展示地址、房号、昵称、口令和“加入房间”。
- 加入后复用同一对局布局，隐藏房主控制按钮。
- 等待批准、被拒绝、地址不可达等情况必须分别显示。

页面组件继续保持纯 props；新增 controller 负责传输、加入审批、重连和状态映射，避免把网络依赖塞进 UI 测试夹具。

## 9. Android 界面

Android v1 作为客人接入：

- 加入页支持粘贴 `IP:端口`，自动解析并校验格式。
- 对局页保持左蓝右红的横向战况条；竖屏使用紧凑布局，分数数字固定在自己的半区。
- 下方展示双方当前分、演唱者、歌词和麦克风状态。
- 逐句音高曲线 v1 延后，优先保证歌词、分数和触控流畅。
- 战况动画使用 CSS transform，避免每帧 React 状态更新。

Android 当房主涉及前台服务和网络权限，v1 暂不做。PC 与 Android 作为客人之间共用同一客户端协议。

## 10. 麦克风与资源

小伊语音和 K歌不能同时占用麦克风：

- 进入 K歌房间时暂停语音助手监听。
- 离开或停止房间后恢复语音助手原设置。
- 麦克风被拒绝时继续播放伴奏，个人分标记“未评估”，公共分不虚构。

退出房间必须释放：

- 麦克风 tracks
- AudioContext 与音频节点
- 评分监听器和计时器
- WebSocket 连接与重连定时器
- 房主媒体连接与成员授权
- 页面级 pending 分数缓冲

## 11. 错误与恢复

必须区分：

- 地址格式错误
- 局域网不可达
- 端口拒绝
- 房号错误
- 口令错误
- 等待房主批准
- 房主拒绝
- 房间已满
- 房间已关闭
- 版本不兼容

房主断线时客户端冻结比分并显示重连状态，不能自行宣布胜负。客人断线后恢复房间快照，补交未确认的行分。

错误提示沿用现有可关闭错误 UI，内容不得溢出容器，关闭按钮必须可操作。

## 12. 安全与网络

- 只绑定局域网接口，不监听公网地址。
- 房号、授权令牌与房间内最小权限分离。
- 拒绝陌生 Web Origin 与伪造 host 身份。
- 限制信封大小、快照大小、成员数、队列长度和事件频率。
- 分数、昵称和文本字段均做长度与范围校验。
- Android 明文本地 WebSocket 仅允许局域网场景，并保留现有加密信封边界。
- 房主只监听本机私网 IPv4。邀请公钥固定房主身份，握手完成后加密传输房号、口令、授权和控制消息。Android 在读取正文前检查帧长度。
- 房主停止时广播 closed，并撤销全部房间授权。

## 13. 实施顺序

1. 核心协议与状态：阵营、battle、score.line、校验、去重、聚合、评级。
2. PC 传输与审批：WebSocket 服务端、IP 列表、房间 controller、审批 UI。
3. PC 对局 UI：战况条、艺术字、房主控制、错误与断线状态。
4. Android 传输与对局 UI：加入流程、重连补交、竖屏布局。
5. 全量 Review、双端协同测试、资源释放与安全回归。

## 14. 多 Agent 分工

### lan_core（前置串行）

负责 `contracts.ts`、`session.ts`、`lan/types.ts`、`lan/protocol.ts`，新建 `lan/score.ts` 与 `lan/battle.ts`。完成成员阵营、公共战况、分数事件、校验、去重、限速、结算和测试。

### lan_transport（核心完成后并行）

负责 PC WebSocket 服务端与客户端、IP/端口获取、加入审批 controller、断线重连、Android 客户端传输适配。不得修改评分聚合规则。

### lan_desktop（核心完成后并行）

负责 `FeatureWorkbench` 入口、PC 建房/加入/对局页面、房主控制、红蓝战况条、评级艺术字和桌面资源释放。

### lan_mobile（核心完成后并行）

负责 Android 加入页、移动房间页、竖屏适配、重连提示和移动端麦克风资源释放。

### review_verify（最后执行）

负责协议与状态 Review、双端协同、断线乱序、刷分限速、敏感字段、资源释放、视觉 QA 和必要测试。遗留问题按旧问题清单定向复核。

并发约束：`lan_core` 先完成并冻结接口；`lan_transport`、`lan_desktop`、`lan_mobile` 再并行；`review_verify` 最后统一收口。所有 Agent 只通过房间快照和分数事件契约协作，禁止相互直接依赖 UI 内部状态。

## 15. 验收标准

- PC 建房并展示可连接的局域网地址、端口和房号。
- PC 与 Android 输入地址、房号后成功申请，房主可批准并分配蓝红方。
- 两端各自本地评分，分数经房主聚合后同步显示。
- 红蓝对冲方向、领先权和分数数字正确，重连后不丢已确认分数。
- 100 分正确显示 WONDERFUL 艺术字，减动效模式生效。
- 暂停、继续、跳歌、结算、重赛全端一致。
- 麦克风拒绝、地址不可达、房号错误和房主拒绝显示可关闭的明确提示。
- 退出房间后所有麦克风、音频、网络和计时资源释放。
- 普通播放器、歌单、个人资料和小伊语音设置不受破坏。
- 单人练唱入口按本版范围隐藏，底层评分引擎仍可被局域网模式复用。

本阶段只做本地开发与测试，不打包、不上传、不改更新通道。

本机曲目优先从音乐库匹配，其次通过已启用的音源查找同名、同歌手的录音。房间共享歌曲名、歌手、时长和比分。本地文件和播放地址留在各自设备，普通录音暂未做人声分离。只有歌曲有可信音高参考时才评估音高。
