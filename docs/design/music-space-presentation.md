# 音乐空间的三种展示方式

## 用户操作

音乐空间与搜索结果共用顶部的“贴纸拼贴 / 多轨环绕 / 简约列表”切换入口。首次使用仍是贴纸；更换风格只改变浏览方式，不更换队列、音乐源或用户歌单。

多轨环绕采用四条相交椭圆轨道。中心拖动或滚轮同时转动四条轨道，在单条轨道上上下拖动或滚轮只改变该轨道。轨道前后按钮和方向键提供另一种浏览方式，歌曲数量不受当前可见卡片数限制。大小滑块范围为 65%–125%。窄屏根据可用区域隐藏相交或背面的卡片，保留中心歌曲和轨道浏览入口。

点卡片／歌名只聚焦，明确点击“播放”才调用原播放链路；只有当前播放歌曲提供“放大”入口。简约列表显示歌名、歌手、专辑、时长、当前状态与既有收藏等操作，按需继续显示歌曲。搜索追加结果不主动重置浏览位置。全屏歌曲详情与纯净歌词仍沿用已有播放器。

## 模块边界

- `presentation.ts` 只保存本地展示偏好，独立存储键，不写个人资料、音乐源或更新配置；写入失败保留原选择，并允许关闭提示。
- `orbitGeometry.ts` 是无状态几何计算；`OrbitSongSpace` 只管理轨道浏览和焦点，不请求音频或自行切歌。
- `SimpleSongList` 只管理展示数量和点击事件，业务操作由宿主提供。
- PC `LatticePlayer` 与移动端 `StickerSpace` 传入同一歌曲集合、分区、原始播放和资料操作。PC 展示适配不把精简对象写回业务资料。
- 非贴纸模式卸载隐藏的贴纸节点并停用其手势，保留相机状态；新风格改变焦点后返回贴纸时使所选歌曲可见。

## 既有书签兼容

既有书签仍表示贴纸镜头、缩放和歌曲引用，不把隐藏的旧镜头冒充环绕位置。新风格保存位置时明确要求切回贴纸；分区加入聚焦歌曲与恢复已有书签仍可用，恢复书签后回到贴纸。

## 验证范围

使用隔离资料的真实 React / Electron 渲染测试两端宿主、轨道手势、列表、选择与播放分离、存储失败、搜索追加、书签和响应式布局。截图检查实际卡片、文字、控件的遮挡与溢出。几何测试覆盖大量歌曲可达性、缩放与碰撞过滤。以上不是手机实机帧率或真实用户资料覆盖安装验收，不操作在用客户端。

新发行沿用既有签名、包名、更新协议和资料位置，使用新的公开版本及递增构建号；保留历史工件和下载地址。
