# 远程音乐助手：本地交付记录

日期：2026-11-05。源码基线 `ca27bc7`。本轮由五个子 Agent 分批负责公共契约、原生传输、业务适配、会话协调、双端界面，主 Agent 完成共享入口接线、阶段 Review、修复及定向复核。

本轮完成源码和必要自动验证，用户随后单独授权上传源码。此次不创建 PR/标签、制作安装器、连接手机、修改更新通道或发布 Release。公开版本及构建号仍为 1.3.0/r59。此前已完成的星轨美化一并保留，没有扩展星轨助手指令。开发和测试未启动、重启或修改正在使用的客户端资料。

## 调用和资料边界

入口 → 会话协调器 → 原生配置读取 → 本地解释器，或模型协议适配器 → PC 主进程 / Android 原生 HTTPS → 工具注册表和参数校验 → 会话引用与确认 → 固定业务适配器 → 既有播放器/个人资料/任务模块 → 业务回执 → 文字、语音和角色状态。

注册表是 24 组工具定义、平台声明和参数验证的唯一来源。模型不能传任意 operation、路径、音频 URL、脚本或客户端确认凭据。引用有所属会话、对象类型、数量和寿命限制，新搜索退役旧候选。确认固定目标，切歌不替换已确认对象；新输入使旧计划失效。

同一请求最多提交一个业务修改。请求 ID、操作 ID 和模型 tool_call_id 分开。重启只读取未确认操作的实际状态，不重放写入、不恢复可执行确认计划。无法唯一确认的结果保留 unknown/partial。回执具有容量和时间清理规则。

Key 一次提交到原生；PC 独立 safeStorage 加密文件，Android 独立 Keystore + no-backup 文件；前端只获得掩码。更换最终服务地址不沿用旧 Key。模型网络与音乐源、更新网络独立，保持正常 TLS/主机名验证，拒绝重定向携带凭据。模型等待上限不改变音乐解析、播放或缓存的状态等待策略。

没有改动用户歌单存储格式、发行密钥、包名、构建身份、更新签名或稳定通道。新增操作回执使用独立存储键，模型配置使用独立加密文件；不是用户资料迁移。本轮没有执行真实覆盖升级验收，不据此宣称新工件升级已经通过。

## 本轮 Review 与修复

评审范围为本轮全部新增文件、共享入口 diff 及必要业务边界，不是对整个仓库所有历史路径的运行保证。先固定基线和调用链，再分层检查契约、状态、权限、持久化和结果显示；确认实际问题后作最小修复，沿同一清单复核。重点问题如下，均已修复：

| 问题 | 触发及后果 | 修复与证据 |
| --- | --- | --- |
| P1 配置切换迟到执行 | 模型完成、持久回执等待或模型失败回退期间原生 revision 改变，旧操作可能继续 | 执行/提交/回退前重查 revision；三处时序回归均通过，测试先复现旧实现失败 |
| P1 确认引用失效 | 计划票据仍有效，但歌曲引用已过期，原指纹仍正确 | 提交前复查会话引用及 TTL；十四分钟准备、十六分钟确认拒绝写入，旧实现失败已复现 |
| P1 低置信命名续答 | 命名续答合成 action，低置信或 NaN 可绕过识别确认 | 非有限值或低于 0.62 必须先识别确认，再资料确认；真实 local bridge 测试 |
| P2 迟到命名追问 | 已取消的异步本地结果重新写入命名状态，影响下一条指令 | 中止后不再写 naming；取消后迟到问名不使新名字触发创建 |
| P2 长会话协议失效 | 历史累积后超过 32 条或拆散工具配对 | 按完整历史对退役；长期连续查询保持消息限额与配对 |
| P2 回执故障传播 | 可选回执损坏连无 Key 本地只读查询也被阻断 | 可信解释器只读预判；查询可用，修改和确认继续保留持久门禁 |
| P2 隔离入口生命周期 | execute-only 和 StrictMode 丢弃实例可能使用普通回执或遗留监听 | 统一隔离判断，隔离实例无全局监听，最后 observer 离开后清理 |
| P2 工作台快捷操作旁路 | 旧快捷按钮直接执行，绕过统一状态和回执 | 固定本地快捷按钮也进入同一协调器；不依赖模型补齐本地片段标记工具，受控验证无模型调用且只提交一次 |
| P2 原生参数范围不一致 | 搜索/漫游/定时工具声明超过业务上限 | 对齐 120 字、临时岔路 1–5、定时 1–720；严格契约测试 |
| P2 查询资料没有展示 | 真实工具只返回摘要消息，结构化歌曲/统计/任务未展示及朗读 | 白名单 formatter 共用于 UI 和语音；控制行数、文本长度且不输出内部路径/引用 |
| P2 歌词和页面状态失真 | 当前句忽略正负偏移；纯净跳转宣称持久保存；组合失败丢失已完成部分 | 当前句沿用播放器偏移；page_opened/needs_input/partial 分开，正负校正测试 |
| P2 选中本地歌曲资料不完整 | 空间快照已剥离 path，直接加入歌单会保留不可播放对象 | 从本机曲库按真实 ID 恢复完整 Track；模型仍只获摘要 |
| P2 漫游及任务上下文不全 | PC 缺省 roaming=false；任务查询只有缓存；空返回也宣称任务建立 | 读取实际漫游状态，合并有限活动并说明覆盖范围；未返回任务不报已建立 |

另核对了独立扩展失败不关闭基础功能、批量部分完成、提交后取消仍观察结果、页面关闭与取消分离、Key 不进入模型资料/日志/皮肤/常规备份、更新网络保持独立。最终定向复核未发现该范围内仍需阻断交付的已确认问题；这不代表不存在尚未发现的缺陷。

- `npm run build` 通过，PC Web 输出在 dist。

- Android `gradlew.bat compileDebugJavaWithJavac --console=plain` 通过，编译实际原生插件和凭据类，未生成安装器或安装设备。

没有调用真实付费模型，因此实际供应商工具调用兼容性、计费和语义准确率未验证。没有验证设备 Keystore/TLS、手机权限交互、真实跨设备协作和真实在线音源。没有制作新发行工件或验收升级。本轮没有已知的未接线交付能力；这些未验证范围不冒充运行验收通过。

## 模型协议及本地入口

首版是 HTTPS、Bearer Key、非流式 Chat Completions tools/function.arguments JSON 字符串。接受基址或最终 /chat/completions 地址；不支持 Responses、SSE、多模态、自定义鉴权头或厂商私有请求字段。连接测试只发一个临时 nonce 工具，不提供业务工具；用户主动点击测试会产生一次模型调用，可能收费。完整规则见 [传输说明](remote-assistant-transport.md)。

本轮没有自动启动验收窗口。后续用户决定验收时，PC 源码客户端入口为“音乐工作台与助手 → 助手 → 模型连接设置”，对话框也有同名折叠入口。配置未启用时可先用原本地命令；配置保存后主动测试，再输入查询/播放/资料操作。资料操作卡只在用户确认后提交。

原生 IPC 的变更需要重新启动对应的源码验收客户端才能加载；仅刷新旧窗口不能加载新的主进程代码。验收应沿用原来的独立资料目录，先正常退出旧实例，不需要合并或清空资料。本机具体路径与启动记录仅留在本地，不随源码上传。

仅看模拟 UI 可使用现有 Vite 开发入口的 `/scripts/fixtures/remote-assistant-ui.html`；它使用受控示例数据，不访问真实 Key 或播放库，不能作为真实模型或完整客户端的验收证明。Android 本轮提供 Web 构建和原生编译结果，安装体验由用户后续决定。
