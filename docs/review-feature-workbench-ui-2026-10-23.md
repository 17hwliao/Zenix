# 音乐工作台集成界面验证

范围为实际 `FeatureLauncher` / `FeatureHost` / `FeatureWorkbench` 及六个真实面板。使用隔离 Vite 与不可见 Electron 窗口；桌面桥接和 Capacitor Android nativePromise/nativeCallback 由 fixture 提供测试数据，不访问用户配置、客户端、音源或设备。

## 确认并修复

P2：工作台懒加载模块失败时，失败提示样式也依赖该模块。真实注入503后，错误提示为 static 布局，关闭按钮被主界面标题盖住，`elementFromPoint` 命中标题，无法点击关闭；工作台尚未挂载时原键盘关闭逻辑也不存在。

修复：`FeatureLauncher.css` 随轻量入口独立加载，使加载/失败提示始终位于可见位置；只在当前 host 已打开、显示 fallback 且没有实际工作台时处理 Escape，尊重已处理事件和其他活动模态对话框。正常工作台继续使用既有焦点处理。

## 实际覆盖

- 工作台打开前不请求工作台模块、不创建音频播放器；准确范围是工作台模块懒加载、六面板按页签挂载，不声称六个独立下载块。
- 桌面和模拟 Android 原生桥接，在1000、390、320像素宽度分别遍历六页签：对话框、内容与页面无横向溢出，关闭按钮实际命中，其他页签组件未挂载。
- 未选中的后台任务面板不启动轮询；Android遍历所有页签仍为0个HTMLAudio，避免加载桌面播放器。
- 关闭按钮、正常Escape、Tab与Shift+Tab首尾焦点包围；关闭后主界面继续可点击，浏览页签不改变既有测试队列。
- 模拟资料读取失败后仍可关闭工作台并操作主界面，无未捕获异常。
- 故意令懒模块返回503，验证错误边界可见、关闭按钮实际可命中、Escape关闭、再次打开后按钮关闭，并确认主界面可继续操作；另验证其他活动模态框不会被fallback Escape误关、host关闭后不吞其他页面Escape。

专用测试 `scripts/Test-FeatureWorkbench.cjs` 已加入 npm test。完整用例修复后1/1通过，约11秒；单项内部包含两平台、三宽度、六页签及故障分支。此前确认样式缺陷时保留失败断言，未放宽命中或布局断言换取通过。

这是实际 Chromium/React 交互与桥接契约检查；不代表Android系统权限、真实手机帧率、音乐源网络、真实设备协作或发行升级验收。
