# 本地音乐漫游 · 第一版

首页或音乐空间点击“开始音乐漫游”，无需选择歌手或主题。没有收听记录时，先搜索并播放一首；音乐源由用户配置。停止漫游保留当前歌曲，暂停后可以继续。普通搜索只改变展示结果，主动播放普通歌曲才退出漫游。

## 推荐方式

推荐规则由 Zenix 自行实现，不调用外部推荐 API，不使用其他项目的推荐算法，也不上传个人偏好。歌曲检索、歌词及播放仍经过已有的音乐源目录和顺序解析机制；检索关键词会发送给用户配置的目录服务。

- 近期收听建立短期方向，喜欢、收藏与歌单建立长期偏好。
- 实际出声的收听时间用于学习；暂停、缓冲和拖动进度不增加有效时长。完整收听权重较高，主动早跳过提供较弱的负反馈。
- 根据歌手、合作歌手和专辑产生多个检索起点，分页获取候选，结合偏好与近期歌手轮换排序。
- 首批有候选即开始播放，后续在后台补充；歌曲结束或点击下一首继续发现新歌。
- 不根据标题宣称准确识别曲风。当前主要依靠目录元数据与歌手关系发现相邻作品，发现范围取决于源提供的目录和元数据。

## 不重复与失败处理

自动推荐使用规范化歌名、排序后的歌手集合及保留的版本名称形成指纹，排除已有历史及漫游中消费过的歌曲。不同源的同名同歌手作品合并，Live、Remix 等明确版本保留。若源的歌名或歌手标注不一致，指纹仍可能无法识别同一录音；系统没有下载整段音频做声纹分析。

选中歌曲后先保存去重记录，再开始播放。去重记录不随音频缓存淘汰，也不按近期历史的 300 首上限裁剪。明确手动点击已展示歌曲的播放按钮可以重听，自动推进不会因此回放旧曲。清除应用数据或重新安装且不保留数据会重置记录。

一首歌沿用现有源接入顺序和音质降级逻辑；所有可用播放源都失败后跳过该候选。网络失败、解析失败和尚未出声的取消不视为用户不喜欢。连续 4 首播放失败暂停并给出重试与音乐源管理入口；新候选耗尽时暂停，不偷偷循环旧歌曲。本地去重记录无法保存时暂停推荐。

## 实现与资源范围

| 平台 | 实现 | 有界候选 |
| --- | --- | --- |
| Windows | `electron/roaming-engine.cjs` 纯规则核心，`src/core/roamingEngine.ts` 构建导入，`src/core/roaming.ts` 管理播放器生命周期 | 最多 30 首待播候选和 10 首已浏览贴纸 |
| Android | `RoamingController.java` 由原生 PlaybackService 管理，独立串行检索与持久化，后台无需 React 定时器 | 最多 80 首候选，最多 60 张展示贴纸 |

两端采用相同的歌曲身份规则和有效收听信号，排序权重按运行环境实现。Android 不增加推荐 WebView、额外运行依赖或常驻页面；Windows 不新增推荐服务进程。永久去重记录随使用增长，其余偏好和候选池有数量上限。

Windows 使用本机 Chromium Local Storage 的 `zenix.roaming.v1`；Android 使用应用私有 `zenix.json` 的 `roaming` 字段，通过 AtomicFile 写入。两端记录独立，当前不做账号同步。第一版保留现有搜索、歌单、缓存、原生通知和歌词入口。

## 本轮交付边界

本轮完成 TypeScript / Vite、Windows NSIS 与 Android Release 构建，以及正式 APK 版本、签名与包内容核对。PC 实际启动查看首页、漫游贴纸、封面和歌词，观察到配置源返回的音频正常推进。本轮没有新增或运行自动化测试；没有连接 Android 真机，后台长时间收听、手机网络切换及长周期推荐质量仍需使用者验收。
